# RuleRunner 段落替换启发式（正文兜底）

日期：2026-11-19；分支 `refactor/rebuild`；基线 HEAD `1c95c12`（研究开始时）。
范围：`RuleRunner.content()` 里「规则输出的正文不足 500 字就用整页 `<p>` 覆盖」这条启发式。只读对照上游 + 离线单测实测；未联网抓真实站点、未做浏览器验收。

## 0. 结论

1. **这是本仓自有的启发式，上游没有对应实现。** 上游只做格式化，正文为空时抛 `ContentEmptyException`（`BookContent.kt:205`）。
2. **旧判据「长度 < 500 且候选更长」会静默把正确正文换成页面评论/页脚。** 本轮用离线单测复现：规则选中 3 段共 144 字的短章，整页 8 段共 286 字（正文 144 + 评论 142），旧代码把正文覆盖成「正文 + 评论」，断言在 `RuleRunnerTest.kt:1466` 失败。
3. **已改为「候选必须明显更多」**：`candidate.length >= max(200, pageText.length * 3)`。144 字的短章（候选 286，1.99 倍）不再被覆盖；规则完全取不到内容时，整页长段落仍能救场（5 段 240+ 字）。
4. 3 倍与 200 字都是启发式阈值，不是从真实站点统计出来的；真实站点回归验证尚未做（本环境 8/8 中文站取回失败，见 §6）。

## 1. 机制

`RuleRunner.content()` 每取一页：

1. 用 `contentRule` 取值 → `preserveContentImages` → `cleanContent()` 得到 `pageText`（`RuleRunner.kt:959`）。
2. 若 `pageText.length < 500`、不是媒体直链（`sniffMediaUrl` 为空）、也不是单行裸 URL（`isBareUrlLine()`），进入兜底（`RuleRunner.kt:960-976`）。
3. 从**原始响应体** `body` 里用正则 `(?i)<p[^>]*>([\s\S]*?)</p>` 取所有 `<p>`，逐段 `cleanContent()`，过滤掉长度 ≤ 2 与三条固定文案（「按←键返回」「加入书签」「仅放置最近浏览」）。
4. 段落数 ≥ 5 时拼成 `candidate`；旧代码只要求 `candidate.length > pageText.length` 就覆盖。
5. 覆盖后照常走 `replaceRegex`、`subContent`、媒体嗅探，最终返回。

上游对照：`BookContent.analyzeContent` 只对 `content` 做 `HtmlFormatter.formatKeepImg`，没有「从页面 `<p>` 反推正文」的路径；空正文在 `BookContent.kt:205` 直接抛 `ContentEmptyException("内容为空")`。所以这条兜底是本仓为「规则写坏但页面仍是标准文本站」加的救援通道。

## 2. 为什么旧判据危险

- **判据只看长度**：规则已经选中正确容器时，整页 `<p>` 天然是它的超集，只要页面有 5 段评论/推荐/页脚，`candidate` 几乎必然更长。
- **静默替换**：没有日志、没有告警，界面直接显示错误内容；用户看到的是「正文里混进评论区」，不是报错。
- **短章是常态**：诗歌、对话体、分页后的尾页都可能 < 500 字。旧代码把「短」当成「规则没取到」，这是判据的语义错误。
- **历史佐证**：0.2.4（`1a20231`）曾给这条兜底补过媒体直链与裸 URL 两道豁免，原因正是「规则明明取到了 88 字的 m3u8/播放页，却被整页页脚顶掉」。这说明触发面过宽早已暴露，只是当时按输出形状逐个打补丁，没有收紧长度判据。

## 4. 改法

`RuleRunner.kt:977` 起：

```kotlin
val floor = maxOf(PARAGRAPH_FALLBACK_MIN_CHARS, pageText.length * PARAGRAPH_FALLBACK_RATIO)
if (candidate.length >= floor) pageText = candidate
```

常量在 `RuleRunner.kt:1612-1616`：

- `PARAGRAPH_FALLBACK_MIN_CHARS = 200`：规则输出为空时，整页段落短于 200 字多半是导航/页脚。
- `PARAGRAPH_FALLBACK_RATIO = 3`：候选至少是规则输出的 3 倍，才算「规则只捞到一小块、整页有更多正文」。

保留的旧条件：`pageText.length < 500`、媒体直链豁免、裸 URL 豁免、段落数 ≥ 5、三条固定文案过滤。

## 5. 残余风险

- **3 倍/200 字是拍的**：没有真实站点分布支撑。可能出现「规则输出 100 字、整页 350 字正文」被 3 倍门槛挡住（漏救），也可能「规则输出 80 字、整页 260 字评论」仍被覆盖（误救）。
- **评论区/页脚仍可能混入**：只要候选达到门槛，整页 `<p>` 里除了正文还有评论/推荐位，仍会一起进正文。当前只过滤三条固定文案。
- **多页正文逐页兜底**：`nextContentUrl` 多页时每页独立判断，尾页正文短、页脚长时可能重复注入页脚。
- **`replaceRegex` 会作用于兜底文本**：兜底发生在 `patterns` 之前，源里针对原规则的替换会作用到整页段落上（可能误删，也可能正好清掉广告）。
- **正文不在 `<p>` 里的站点救不了**：兜底只认 `<p>`，`<div>`/`<br>` 排版的站点仍然失败。
- **未做真实站点验证**：本轮只跑离线夹具，没有抓取真实页面确认「144 字短章 + 评论区长」这种形状在现网的比例。

## 6. 没做 / 不知道
