## 0. 先看结论

1. **研究重点应放在规则语义与阅读状态，而不是仅看技术栈。** 本仓已经有搜索到正文的执行链，但组合规则的求值方式、错误变空值和正文兜底，会直接影响同一书源的结果；详见 §1–3。
2. **不能用“有测试”代替“兼容已证明”。** 现有 golden 正文断言没有锁定完整输出，也没有在本轮与 Android 上游双跑；见 §4。
3. **文档必须按时间与源码核对。** 当前 AI 路由已经撤出，数据库已有版本迁移；这些事实与部分旧说明不同。版本一致性校验仍有一项失败；见 §5–6。

## 1. 搜索、目录、正文怎样进入取值

- `searchWithReason → SearchFlow.search → fetchSearchPage → bookItems`：执行 URL 脚本、合并请求选项后抓取；`bookList` 产出节点，每项通过 `NodeValue.value` 提取名称、地址等，缺名称或地址即丢弃。[SearchFlow.kt:58](../../product/app/src/main/kotlin/io/legado/rules/SearchFlow.kt#L58)、[RuleRunner.kt:169](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L169)、[RuleRunner.kt:240](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L240)
- `chaptersImpl → parseTocPage` 用 `chapterList` 选节点，再取 `chapterName/chapterUrl`；`contentImpl → contentPage` 则从根节点取 `content/nextContentUrl`，随后清理、替换、拼页。两者都有回环与页数限制。[RuleRunner.kt:741](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L741)、[RuleRunner.kt:803](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L803)、[RuleRunner.kt:950](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L950)

## 2. 调度不是统一的“失败就换解析器”

- `RuleDispatcher` 按注册顺序认领，`canHandle` 异常视为不认领；一旦认领，空值或执行失败都不退回内建。列表只询问 `producesNodes` 处理器。[RuleProcessor.kt:118](../../product/app/src/main/kotlin/io/legado/rules/RuleProcessor.kt#L118)、[RuleValue.kt:45](../../product/app/src/main/kotlin/io/legado/rules/RuleValue.kt#L45)、[RuleNodeSelection.kt:45](../../product/app/src/main/kotlin/io/legado/rules/RuleNodeSelection.kt#L45)
- 内建列表先辨正则 `:`、XPath、`@json:`，再切组合，最后处理 `$` 路径或 CSS；JSON 裸键列表无结果还会落到 CSS。字段按节点类型走 JSONPath，HTML 才辨 XPath/CSS；字段坏选择器可变空，不代表列表也吞错。[RuleNodeSelection.kt:59](../../product/app/src/main/kotlin/io/legado/rules/RuleNodeSelection.kt#L59)、[RuleValue.kt:426](../../product/app/src/main/kotlin/io/legado/rules/RuleValue.kt#L426)
- `&&` 合并、`%%` 交错、`||` 取首个非空；切分由最左分隔符决定，避开花括号、方括号、引号及正则段。**进入组合规则分支时，值级 `||` 先算全部分支，列表级才短路**；值级入口明确排除了内联 JS 和 `<js>` 等情况，不能把该结论套到 JavaScript 自身的 `||`。[RuleSplit.kt:105](../../product/app/src/main/kotlin/io/legado/rules/RuleSplit.kt#L105)、[RuleValue.kt:133](../../product/app/src/main/kotlin/io/legado/rules/RuleValue.kt#L133)、[RuleNodeSelection.kt:71](../../product/app/src/main/kotlin/io/legado/rules/RuleNodeSelection.kt#L71)
- `@put/@get`、模板和 `##` 替换参与取值；纯 JS 失败可为空，前置规则接 JS 失败却保留前值，`<js>` 后还能接新文档取值。正文另有启发式兜底：非媒体、非裸 URL 的结果不足 500 字，若有至少五段且更长，会被整页段落替换，**不要求原结果为空**。[RuleValue.kt:81](../../product/app/src/main/kotlin/io/legado/rules/RuleValue.kt#L81)、[RuleValue.kt:161](../../product/app/src/main/kotlin/io/legado/rules/RuleValue.kt#L161)、[RuleRunner.kt:959](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L959)

## 3. 可证实的宿主边界

- `JsSandbox` 使用 Rhino 安全标准对象、禁 Java 反射，`Packages` 是手写白名单，不是任意 JVM/Android 类加载器；`android.os.Build` 甚至是固定设备值。不能据包名存在推定完整 Android 能力。[JsSandbox.kt:300](../../product/app/src/main/kotlin/io/legado/rules/JsSandbox.kt#L300)、[JavaPackages.kt:86](../../product/app/src/main/kotlin/io/legado/rules/JavaPackages.kt#L86)、[JavaPackages.kt:561](../../product/app/src/main/kotlin/io/legado/rules/JavaPackages.kt#L561)
- `startBrowserAwait` 首轮记录打开请求、返回空 body；完成后重跑，使用回传 HTML 或服务端重抓，不是保持原脚本阻塞等待。另有 `mainJs → JsSourceRunner` 独立路径，其 `java` 仅安装 `ajax`，不能套用 `JsSandbox` 全套桥能力。[JsSandbox.kt:1287](../../product/app/src/main/kotlin/io/legado/rules/JsSandbox.kt#L1287)、[RuleRunner.kt:1662](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L1662)、[RuleRunner.kt:1686](../../product/app/src/main/kotlin/io/legado/rules/RuleRunner.kt#L1686)

## 5. 把规则引擎放回产品全景

### 启动与运行形态

- 根 `npm start` 转发到 `product/start.mjs`，由脚本启动 Java jar；它不是 Node 后端。桌面入口则在同一 JVM 启动服务，再打开浏览器应用窗口。[package.json:11](../../package.json#L11)、[product/package.json:31](../../product/package.json#L31)、[product/start.mjs:369](../../product/start.mjs#L369)、[DesktopLauncher.kt:170](../../product/app/src/main/kotlin/io/legado/DesktopLauncher.kt#L170)、[DesktopLauncher.kt:344](../../product/app/src/main/kotlin/io/legado/DesktopLauncher.kt#L344)
- 当前 Ktor 服务引擎是 **Netty**，不是旧架构图里的 CIO。启动脚本默认 `127.0.0.1:1234`，裸服务配置默认 `127.0.0.1:8080`，不能把两种入口混为一谈。[Application.kt:76](../../product/app/src/main/kotlin/io/legado/Application.kt#L76)、[runtime.mjs:38](../../product/scripts/runtime.mjs#L38)、[ServerConfig.kt:48](../../product/app/src/main/kotlin/io/legado/ServerConfig.kt#L48)

### 阅读、分页与持久化

主链可概括为：前端章节加载 → 正文 API → 服务端缓存／规则抓取 → 内容呈现；位置另经进度 API 保存，分页依赖浏览器实际布局。

- `useReaderChapterContent` 优先使用预加载结果，否则请求 `api.content`；普通请求失败可回退浏览器离线缓存，强制刷新不走该回退。[useReaderChapterContent.ts:100](../../product/web/src/features/reader/useReaderChapterContent.ts#L100)、[search.ts:106](../../product/web/src/lib/api/domains/search.ts#L106)
- 后端 `/api/books/content` 区分本地书、缓存命中和网络抓取；网络正文调用 `runner.content`，有书籍地址时写回章节缓存。[ReadingRoutes.kt:140](../../product/app/src/main/kotlin/io/legado/http/ReadingRoutes.kt#L140)、[ReadingRoutes.kt:182](../../product/app/src/main/kotlin/io/legado/http/ReadingRoutes.kt#L182)
- 分页读取 `clientWidth`、`scrollWidth` 和 `Range.getClientRects()`；纯函数测试不能单独证明真实字体、栏宽、跨章排版正确。[usePaginationMeasurement.ts:65](../../product/web/src/features/reader/usePaginationMeasurement.ts#L65)
- `ReaderScreen.persist` 同时保存章节、滚动位置和逻辑位置，经 `ReadingRepository` 落库；当前前端保存调用会吞掉失败，因此“调用了保存”不等于“位置已持久化”。本轮未复现丢进度。[ReaderScreen.tsx:816](../../product/web/src/features/reader/ReaderScreen.tsx#L816)、[ReadersRoutes.kt:29](../../product/app/src/main/kotlin/io/legado/http/ReadersRoutes.kt#L29)、[ReadingRepository.kt:37](../../product/app/src/main/kotlin/io/legado/reading/ReadingRepository.kt#L37)
- SQLite 使用多读连接、单写连接加锁；初始化已在事务中调用 `SchemaVersion.migrate`，按 `PRAGMA user_version` 逐级迁移，并拒绝用旧程序打开更高版本数据库。因此不能沿用早期“没有 schema version”的判断。[ConnectionPool.kt:19](../../product/app/src/main/kotlin/io/legado/data/db/ConnectionPool.kt#L19)、[ConnectionPool.kt:60](../../product/app/src/main/kotlin/io/legado/data/db/ConnectionPool.kt#L60)、[Database.kt:163](../../product/app/src/main/kotlin/io/legado/data/Database.kt#L163)、[SchemaVersion.kt:63](../../product/app/src/main/kotlin/io/legado/data/SchemaVersion.kt#L63)

### 功能边界与安全边界

- 根 README 仍列 AI 对话、模型连接和 MCP，但实际路由装配已经不注册 AI 域。注意这不等于所有相关代码已删除：正文路由仍读取历史 `ai_clean` / `ai_rewrite` 覆盖记录。[README.md:29](../../README.md#L29)、[Routes.kt:70](../../product/app/src/main/kotlin/io/legado/http/Routes.kt#L70)、[ReadingRoutes.kt:154](../../product/app/src/main/kotlin/io/legado/http/ReadingRoutes.kt#L154)
- `SameOriginWriteGate` 是浏览器跨站写保护，不是用户身份认证；没有 Origin 的请求放行，且有只读 POST 等例外。默认本地服务的设计不能直接理解成适合公网多用户部署。[Guard.kt:72](../../product/app/src/main/kotlin/io/legado/http/Guard.kt#L72)、[Guard.kt:105](../../product/app/src/main/kotlin/io/legado/http/Guard.kt#L105)
