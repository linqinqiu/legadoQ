## 0. 先看结论

1. **门禁是目录级静态 import 白名单比对，粒度到 `features/<域>` 这一层为止。** 它只挡跨功能域互引（`features/reader` → `features/bookshelf`），对 `features/reader/` 内部的子目录互引、props/回调/Context 状态耦合、上帝组件的 setter 扇出三类纠缠**结构性看不见**。判据全绿只能证明"没跨域 import"，不能证明"单一功能可独立修改"。
2. **当前 `ReaderScreen.tsx` 是 2,389 行、34 个 `useState`、34 个 `useRef`、27 个 `useEffect` 的编排中枢**（命令见 §3）。状态纠缠的载体不是目录，而是 `currentRef` / `logicalMetaRef` / `pageIndex` 这几个被多功能同时读写的共享对象，加上一批 effect 间传意图的 ref。
3. **"测试通过"与"可独立修改"之间缺的是端到端判据**：`REBUILD_PLAN/15` 自己记着交互矩阵"端到端有判据 0 行"。现存判据几乎都是纯函数单测，锁不住"开书→落章→停手落库→切章记当前章"这条链，因此改进度/正文/锚定任一条都可能悄悄改变行为而测试仍绿。
4. **一个明确的双面证据**：工作树里在途的进度改造把"3 处散落的 1200ms 定时器"收进 `useReaderProgress`/`progressSaver`，但同时保留了旧的 `reportProgress` 三处上报——**落库与显示成了两套通道**，正是"看起来收口了、实际又多一个共享点"的样本（§5）。

## 2. 三个盲区（门禁视线之外）

### 盲区 A：同一 feature 子目录互引，永不入集合

`:164-165` 只有 `target[1] !== ownFeature` 才记入 `crossFeature`。阅读器内部 `content/`↔`interaction/`↔`tts/`↔`settingsPanel/` 的目标首两段恒为 `features/reader`，`target[1] === ownFeature === 'reader'`，恒相等、恒跳过。当前实际存在的内部互引（只读 `grep` 实证）：

- `content/contentImages.ts:3`、`content/mangaPages.ts:3`、`content/readerImage.ts:2` → `../interaction/readerInteractions`
- `tts/useReaderTts.ts:20-21`、`tts/ttsEngine.ts:2`、`tts/TtsSettingsModal.tsx:5`、`tts/ttsTextProcessor.ts:1` → `interaction/` 与 `settingsPanel/`
- `settingsPanel/readerSettings.ts:2-6`、`readerConfigRegistry.ts:21`、`backupPreferences.ts:3`、`OtherSettingsPanel.tsx:6-7`、`TypographyTab.tsx:3` → `interaction/` 与 `content/`

这些边在门禁里一条都不计。注意：静态纯函数目录之间互引本身不算坏味道，盲区的意义是——**当这些目录之间出现状态读写（而非纯函数调用）时，门禁同样沉默**。

### 盲区 B：props / 回调 / Context / 共享 hook 的状态耦合

`:113` 只认 import 文本，不解析符号、不追踪数据流。因此下面这些耦合与门禁完全无关：

- `ReaderScreen.tsx:816-830` 把 `readProgressSnapshot` 函数作为 `readSnapshot` 交给 `useReaderProgress`；hook 反过来用 `useSyncExternalStore` 把 `persist`/`state` 交回（见 §5）。
- `useReaderChapterContent.ts:51-52,97` 把父传的 `onLoaded` 存入 `onLoadedRef.current`，加载完成后回调改父状态；注释 `:29` 明说放 ref 是为了绕开依赖数组——**这正是门禁看不见的"回调反写"，也是 effect 隐式耦合的来源**。
- `ReaderScreen.tsx:844-858` 传 `persist`/`changeChapterRef` 进 `useReaderTts`，TTS 又回调切章、切章再 `stopTts`（§4）。

### 盲区 C：上帝组件与 setter 扇出

门禁不统计组件体积、不统计一个 setter 被下发到多少子组件。`ReaderScreen.tsx:71-633` 一段里聚集 30+ 个 `useState`/setter；`:1110-1125` 把 `setPageIndex` 等 setter 直接下发进 hook/展示层。同页布尔弹层开关密集：`tapZoneEditing`(:137)、`toolbarsVisible`(:138)、`showSourceSwitch`(:150)、`isFullscreen`(:151)、`showReplaceRules`(:161)、`offlineStatsModal`(:162)、`showRefreshChapters`(:163)、`localSyncing`(:164)、`bookSearchOpen`(:626)、`reviewsOpen`(:628)——**每个都是"一个功能的状态摆在全局编排层"**，任一开关的语义调整都要回到这个组件。
