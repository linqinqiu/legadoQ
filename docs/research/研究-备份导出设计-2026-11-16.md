# 研究：备份导出（N-2）设计与范围

> 日期：2026-11-16 ｜ 仓库：`E:\legado` ｜ 起点 `main` @ `1ced4fe`
> 承接：[研究-外部建议核对-2026-11-14](研究-外部建议核对-2026-11-14.md) §3 的 N-2、
> `docs/engineering/audit/BACKUP_MATRIX.md` §6 第 4 条「导出与导入同时设计」
> 性质：**只读设计**。本轮未改产品代码。

## 0. 结论（先看这里）

1. **先做「核心五域」的导出，不做「全库镜像」**：书源、替换规则、书架（含进度）、分组、RSS 订阅源。
   这五域是 `BackupImporter` 现在**能原样恢复**的部分（`commit()` 的六步），导出后必然可往返。
2. **笔记/书签/高亮、登录凭据、封面二进制、日志与缓存不进 v1**。前两类不是"忘了"，是**导入侧还没有解析**：
   `BackupImporter` 只把它们当 kept 文件原样收（`BackupStore.KEEP_NAMES`），
   导出再导回来不会回到 `book_note` —— 先做会得到"看起来有备份、恢复后没有"的假承诺。
3. **v1 用一个只读 GET 出 zip**，文件名与上游 `help/storage/Backup.kt` 一致，
   让导出的包能直接喂给手机 Legado；加密（密码包）留到 v2。

## 1. 为什么现在做

- 导入已经是单向漏斗：`POST /api/backup/import` 能吃手机备份，但没有任何出口；
  用户协议里却写着「重要数据请自行导出备份」（`web/src/lib/agreement.ts`）—— 目前只能导出**书源**。
- `BACKUP_MATRIX` §6 明确要求导出与导入**同时设计**，否则字段映射只经得起单向验证。
- 往返判据（导出 → 新库导入 → 字段比对）是导入侧字段映射唯一的**双向**证据。

## 2. 导出什么（文件 → 表 → 字段）

包内文件名取上游现行写法（`BackupImporter` 的 `SOURCE_NAMES` / `RULE_NAMES` / `SHELF_NAMES` 都认小写与目录前缀）。

| 包内文件 | 来源表 | 字段映射 |
| --- | --- | --- |
| `bookSource.json` | `source.payload` | **原样输出**（payload 就是上游 JSON；导入侧 `exportSources` 已按同一口径工作） |
| `replaceRule.json` | `replace_rule` | `name` / `group` / `pattern` / `replacement` / `isRegex` / `scope` / `excludeScope` / `scopeTitle` / `scopeContent` / `isEnabled` / `order` / `timeoutMillisecond`（与 `ruleOf` 逐字段对齐） |
| `bookshelf.json` | `book_shelf` + `reading_progress` | `name` / `author` / `bookUrl` / `origin`(=source_id) / `tocUrl` / `coverUrl` / `kind`（`completed=1` → 「完结」）/ `durChapterIndex` / `durChapterPos`(=char_offset) / `durChapterTime`(=last_read_at) / `group`(=group_id) |
| `bookGroup.json` | `book_group` | `groupId` / `groupName` |
| `rssSources.json` | `rss_source.payload` | 原样输出 |

导出前需要 join 的两处：

- 书架条目的进度在 `reading_progress`（主键 `source_id + book_url`），不在 `book_shelf`；
  没有进度行时 `durChapterIndex/Pos/Time` 取 0。
- `book_shelf.completed` 是布尔，上游是 `kind` 文本（`contains("完结")`）；导出写「完结」/空串。

## 3. 不导出什么（以及为什么）

| 不导出 | 理由 | 后续 |
| --- | --- | --- |
| `cookies.json` | 明文登录态落盘 = 拿到包就能冒充用户。上游用备份密码 AES 加密（`BackupAes` 已在仓库里） | v2：`?password=` 时走同一套 AES，包内写明 `encrypted` |
| `bookmark.json` / `highlight.json` | 导入侧只当 kept 文件收，不进 `book_note`；导出会造成"恢复了但笔记不在" | 先给 `BackupImporter` 加 `bookNote.json` 解析，再导出 |
| 封面 `covers/`、本地书文件 | 体积不可控（真实库封面可达数百 MB），且导入侧不解包 | 单独「媒体导出」按需做 |
| `log_entry`、`book_content_cache`、`script_cache`、`source_health` | 本机运行产物，不是用户数据 | 永不导出 |

## 4. 接口形态

```
GET /api/backup/export            → application/zip，Content-Disposition: attachment
GET /api/backup/export?domain=shelf  → 只导某一域（调试/排查用）
```

- **只读 GET**，不过同源写门（不写任何状态）；仍受回环绑定与现有反代头策略约束。
- 流式写：用 `respondOutputStream` 边查边写 zip，不把整库读进内存；单文件上限沿用导入侧的 64 MB。
- 文件名：`legadoq-backup-YYYYMMDD-HHmm.zip`（时间取服务器本地时区）。
- 端点计数：`ApiCatalog` 165 → 166，需同步 `docs/API-REFERENCE.md`（`npm run docs:api`）。

## 5. 往返判据（验收标准）

新增 `BackupExportRoundTripTest`（后端，JUnit 4）：

1. 造一个临时库：2 条书源（含一条带 `ruleContent` JS）、1 条替换规则、1 本书（进度 = 第 7 章 / 偏移 123 / 时间 T）、1 个分组、1 条 RSS。
2. `export()` → 字节流；用 `ZipInputStream` 断言五个条目都在、且 JSON 可解析。
3. 把字节流写进临时文件、喂给公开入口 `BackupImporter.import(file)` 到**另一个空库**。
4. 逐字段比对：书源 payload 字符串相等、规则 12 个字段相等、书架 11 个字段相等、分组 id/name 相等、RSS payload 相等。
5. 反向对照：导出包去掉 `bookshelf.json` 后导入，书架必须为空（证明判据不是"任何包都绿"）。

另加一条**稳定性**判据：同一库连导两次导出包，行数不翻倍（与 `BackupImportAtomicTest` 的幂等口径一致）。

## 6. 开放问题（实施前需要拍板）

1. **分组 id 冲突**：导出保留原 `groupId`，导入到已有分组的库会撞号。导入侧现在是"按 id upsert 名字"；
   往返测试用空库不受影响，但真实场景要不要重映射？（建议 v1 保持原 id，与上游行为一致）
2. **`kind` 丢失**：我们的书架没有 `totalChapterNum` / `latestChapterTitle`，导出的条目在手机端会显示"未知章节数"。
   可接受（不影响接着读），但要在导出说明里写清。
3. **大库体积**：5,600 条书源约 30–40 MB JSON，zip 后约 5–8 MB。是否要在界面上给"预计大小"？
4. **是否允许导到浏览器下载**：`Content-Disposition: attachment` 即可；桌面壳（WebView）需要确认下载目录策略。

## 7. 实施顺序（下一轮）

1. `backup/BackupExporter.kt`：纯函数 `exportTo(zipOut, domains)`，不碰 HTTP。
2. `BackupExportRoundTripTest` 先红后绿（先写判据）。
3. `GET /api/backup/export` + `ApiCatalog`/`API-REFERENCE` 同步。
4. 前端 `web/src/plugins/backup/BackupPage.tsx` 加「导出备份」按钮（下载 zip），文案写清"不含登录凭据与笔记"。
5. `docs/功能说明.md` / `compatibility.md` / `STATUS.md` 同步。

## 8. 落地记录

### 8.1 第一域：书源（2026-11-16）

| 项 | 内容 |
| --- | --- |
| 实现 | `backup/BackupExporter.kt`（流式写 zip，`finish()` 后不 close 调用方的流）+ `SourcesDao.forEachSourcePayload`（游标逐条，不先 `buildList` 进内存）+ `GET /api/backup/export?domain=source` |
| 包形状 | 单条 `bookSource.json`，内容是一整个 JSON 数组，每条是 `source.payload` 原文（`BackupImporter` 认这个名字与形状） |
| 接口 | 只读 GET；`Content-Disposition: attachment; filename="legadoq-sources-<yyyyMMdd-HHmm>.zip"`；未知 domain → 400 `invalid_domain`（不静默降级） |
| 判据 | `BackupExportRoundTripTest` 2 项：导出 → 空库导入 → 逐条 payload 相等；空库导出 `[]` |
| 实测 | 隔离数据目录起真实服务（`LEGADO_DATA_DIR` + `LEGADO_HOME` 都要指到临时目录）：导入 2 条源 → 导出 245 B zip / `bookSource.json` 181 B，两条都在；`domain=shelf` 400 |
| 契约 | 端点 165 → 166，`agent-api.json` / `API-REFERENCE.md` / `ApiCatalog.test.ts` 三处同步 |
| 未做 | 前端按钮**故意等其余域补齐再上** —— 现在只有一个域，按钮只能叫"导出书源"，而书源导出本来就另有入口；叫"导出备份"则是 §3 说的假承诺 |

**踩过的坑（写下来防复发）**：裸跑 jar 时只设 `LEGADO_HOME` 不够，库路径由 `LEGADO_DATA_DIR` 决定
（`ServerConfig.fromEnvironment`：`databasePath = LEGADO_DATABASE ?: LEGADO_DATA_DIR/legado.sqlite`）。
第一次实测漏了这个，服务连上了**真实库**并往里面导了两条测试源；已按 id 删除并核对源数回到 5,601。
做这类"写数据"的实测，两个变量必须一起指到临时目录。

### 8.2 第二域：替换规则（2026-11-17）

| 项 | 内容 |
| --- | --- |
| 实现 | `BackupExporter.exportReplaceRules` + `GET /api/backup/export?domain=replaceRule`（别名 `domain=rule`） |
| 包形状 | 单条 `replaceRule.json`，内容是一整个 JSON 数组；字段名与 `BackupImporter.ruleOf` 逐一对齐（`id` / `name` / `group` / `pattern` / `replacement` / `isRegex` / `scope` / `excludeScope` / `scopeTitle` / `scopeContent` / `isEnabled` / `order` / `timeoutMillisecond`） |
| 空值处理 | 可选字段为空时**整个键不写**。写成空串会让导入侧拿到 `""` 而不是 `null`，往返比对当场就挂 —— 这条是被判据逼出来的，不是设计时想到的 |
| 不做流式 | 替换规则是几十条量级、单条十几到几百字节，先拼数组再写，峰值几十 KB；为它套游标只会把代码复杂化。量级变了再照 `exportSources` 改 |
| 文件名 | `legadoq-replace-rules-<yyyyMMdd-HHmm>.zip` |
| 判据 | `BackupExportRoundTripTest` 加一项：导出 → 空库导入 → 13 个字段逐条相等（`id` 也带，导入按 id upsert） |
| 实测 | 临时实例 POST 两条规则 → 导出 422 B zip / `replaceRule.json`；原样 `POST /api/backup/import` 回来 `rulesUpdated=2`、`errors=[]`；`domain=shelf` 仍 400，`domain=source` 不受影响（148 B） |
| 未做 | 前端按钮仍等五域齐；书架 / 分组 / RSS 待补 |

### 8.3 第三域：分组（2026-11-17）

| 项 | 内容 |
| --- | --- |
| 实现 | `BackupExporter.exportBookGroups` + `GET /api/backup/export?domain=group`（别名 `domain=bookGroup`） |
