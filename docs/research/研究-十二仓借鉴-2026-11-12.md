## 摘要

1. **最高 ROI 在「选色」而不是「复刻组件」**：komikku 的「按每本封面自动生成主题色，用于详情页与阅读器」[核实] + MaterialKolor 的 seed→scheme 方法论 [核实]，正好接在 legadoQ 已有的封面缓存代理与 `ui/` 颜色内核上；纯前端、零运行时依赖 → P0。
2. **第二高 ROI 是 rimvoid 的「页面模板 = HTML/CSS/JS」** [核实]：把阅读排版外置成用户可编辑模板。legadoQ 是 Web，模板天然就是 DOM+CSS，**没有 WebView 翻译成本**，与 S2「主题导入导出」是同一条产品线 → P0（先只做 CSS-only）。
3. **三个 Compose 组件库（COUI / miuix / mochi）一行 Kotlin 都搬不了**，唯一价值是把「软弹、跟手、玻璃」量化成可抄的数字（例如 Backdrop 的 `pressedScale = 1.5f`、`visibilityThreshold = 0.001f`）→ 只抄参数与配方，见 §二链 B/C。
4. 12 仓里有 4 仓同血统（gedoor → Luoyacheng → rimvoid → HapeLee），**书源语法增量**比 UI 借鉴更能直接变现；但必须先按 §四 的符号表去 `rules/` 三个大文件核对，别按二手描述改。
5. **gedoor/legado 公开仓已被侵权公告清空** [核实]（README 只剩公告 + 阅文保护链接），不能当代码参考源，只能经 gitee 镜像与下游分支间接取证。

## 二、跨仓合成：三条可实施链

### 链 A：封面 → 种子色 → M3 动态主题（Gramophone × MaterialKolor × komikku）
- **数据流**：书籍封面 URL（后端封面缓存代理）→ 前端取图 → 离屏 canvas 缩到 ~64×64 → 采样像素 → MCU 量化得 seed → `schemeFromSeed(seed, variant)` → 该书的主题覆盖（16 个变量）→ 详情页/阅读器以 `data-book-theme` 覆盖 `.theme-*`。
- **状态**：seed 与 variant 存**书级**（S2 书级字段），全局仍是 7 套皮肤；优先级 书级 > 全局皮肤 > 系统深浅。缓存键 `bookId + coverHash`，切书不重算。
- **失败降级**：① canvas 跨域污染（封面代理需 CORS 头）→ 静默回落到「全局皮肤 seed」；② 彩度低于阈值（灰封面）→ 用默认 seed，不允许「抽到灰色主题」；③ MCU 抛错 → try/catch 到 fallback；④ 首屏不阻塞：先用全局皮肤渲染，取色完成后**一次性批量**写 CSS 变量。
- **证据**：komikku 明确「按每本封面自动生成主题色，用于详情页与阅读器」[核实]；MaterialKolor palette 模块即「从图片取 seed」[核实]；Gramophone 只借「封面为大」的版式 [推断]。

### 链 B：软弹跟手动效（mochi × COUI / miuix）
- **数据流**：指针事件（pointerdown/move/up）→ 归一化 `progress∈[0,1]` 或 `velocity` → 弹簧/阻尼求解（已有 `linear()` 弹簧）→ 写 CSS 变量（`--press-scale` / `--drag-x` / `--glow-angle`）→ `ui/motion/` 的类消费。
- **状态**：每个可交互元素四态 `idle | pressed | dragging | settling`；`dragging` 期间禁用过渡，`settling` 用弹簧回位；`prefers-reduced-motion` 直接跳终态。
- **失败降级**：① 长列表掉帧 → 只留 scale + opacity，关 blur/metaball；② `pointercancel` 未收口会卡在 pressed → 统一在 `pointerup/pointercancel/lostpointercapture` 复位；③ 与 `dragSort` 的长按 250ms 冲突 → 按下先进 pending，250ms 后才允许拖，之前只做按压反馈。
- **证据**：mochi 的「按住放大、拖动跟手、融球、橡皮筋、数字逐位滚动」[核实]；COUI 的「跟手动效 + 轮廓光」[核实]；miuix 的 squircle / glass 独立模块 [核实]。

### 链 C：玻璃材质（AndroidLiquidGlass）
- **数据流**：背景图层（对应 `layerBackdrop` 概念）→ 玻璃片：`backdrop-filter: blur(Npx) saturate(S)` + 半透明填充 + 1px 内高光 + 外阴影 → 可选折射：SVG `feDisplacementMap`（渐变噪声作位移图）或径向内高光 → 参数全走 `--glass-blur / --glass-sat / --glass-rim / --glass-refract`。
- **状态**：`glass: off | tint | blur | refract` 四档，默认 `blur`；`refract` 只在「浮动球 / 阅读器菜单」这类小面积组件开。
- **失败降级**：① 不支持 `backdrop-filter` → `@supports` 回落为不透明 `--surface`；② 滚动中大面积 blur 掉帧 → 滚动期间临时降 `--glass-blur` 或直接 off，滚动结束恢复；③ 打印/导出/截图态强制 off；④ 与 7 套皮肤共存：玻璃**只吃** `--surface` 与 `--line`，不引入新颜色。
- **证据**：库自述无高层组件、API 为 `drawBackdrop/effects.blur/effects.lens/Highlight/Shadow` [核实]；`pressedScale = 1.5f` 等是可直接借用的动效基线 [核实]。

## 三、明确不移植清单

1. **Compose 组件本体**（COUI / miuix / mochi 的 Kotlin 实现）：运行时是 Compose/Skia，legadoQ Web 是 DOM+CSS，API 无法映射 [核实：三者均为 Compose 库]。
2. **Compose Multiplatform 的 Web(Wasm) 目标**：miuix 标了 Web 支持 [核实]，但那是 Canvas 渲染，拿不到 DOM 语义、可访问性、文本选择与 CSS 主题，与 legadoQ 的 React 栈是两套世界。
3. **`miuix-glass` / Backdrop 的 GPU 效果实现**：依赖 Android minSdk 33 与 AGSL 运行时 [核实：miuix-glass requires minSdk 33]，浏览器只有 `backdrop-filter` 与 SVG filter 的近似 [推断]。
4. **WebView 内核能力**（legado 系 `webView()` / `BackstageWebView` / Paged.js 排版）[核实：`AnalyzeUrl` 的 webView option、`JsExtensions.webView()`]：legadoQ 没有内嵌浏览器内核，只能走 HTTP + 前端 CSS 分页；应做「能力缺失提示」，不要伪造成功。
5. **Rhino / JS 沙箱语义 1:1 复刻**：上游用 Rhino 跑 `java.*` 桥 [核实：`JsExtensions.kt` 的桥函数]，legadoQ 侧是自研 `rules/JsSandbox.kt`，语义差异属既有事实，本轮不扩大。
6. **本地 OCR / 本地文件智能扫描 / EPUB 原生解析**：依赖 Android 本地文件系统与原生库，Web 端无对应沙箱且在浏览器里收益低 [推断]。
7. **Tachiyomi 扩展生态**（komikku 的 source extensions）：APK 插件机制，与 legadoQ 书源模型不同源 [核实：komikku 为 Tachiyomi 分支]。
8. **`.red` 高亮规则的完整实现**：仅图片背景/边框等 CSS 效果在 EPUB(WebView) 模式下成立 [核实]；Web 端可做，但优先级低于封面取色与模板，本轮不排期。
9. **DoH/分流、定时任务、跨应用悬浮窗听书**：均为 Android 系统能力 [核实：rimvoid 功能表]，Web 端由宿主决定。
10. **内置版权主题**（Minecraft / 明日香 / 诡秘之主等）：只借「模板机制」，内置素材涉及第三方版权与 data URI 体积 [核实：模板文档列了来源与许可]，legadoQ 不自带。
