## 0. 一句话结论

**能继续做细节性演进，但不适合再做「大搬家 / 换框架」式重构。** 分层本身是干净的，六条后端架构判据 + 三条前端判据都在真实执行（不是文档摆设）；真正的阻力不在目录，而在三件事：**测试钉源码文本**（拆 hot 文件先红）、**兼容层 `lib/api.ts` 指路反了**（65 个文件走旧入口）、**插件 runtime 是死层**（注册 0 调用）。先把这三件事降成本，后面的拆分和能力补齐才划得来。

## 2. 分层判据是真的在跑（这是「能演进」的底气）

后端 `ArchitectureBoundaryTest.kt` 六条：Java 桥白名单**严格相等**、`model` 零反向依赖、`rules` 不得 import `data/source/http` 具体类（基线 `emptySet`）、`http` 只被组合根与自身 import（零基线）、`engine→infra` 基线 4 条、包 2-环基线 4 对（`data↔source`、`cache↔data`、`data↔ops`、`content↔rules`）。规则在 `:61/:82/:99/:123/:145/:175`，辅助 `serverDir()`/`readServerFile()`/`scanCodeLines()` 在 `:203-247`。

前端 `ArchitectureBoundary.test.ts` 三条零基线：`features` 互引 0、`shared→features` 0、无 `pages/`；另有 `depth-check.mjs` 的 `KNOWN_DEEP`（只许单调缩小）。

端口也不是纸面架构：`PortBundle` 被 23 处引用 / 6 个文件，5 个访问器共 49 次调用。`rules/RuleHttp.kt:3` 只 import `port.logNetwork`——上一轮记录的 WIP 越界已在 HEAD 修掉。

**本轮补的判据**：新增 `product/app/src/test/kotlin/io/legado/RouteMountTest.kt`，双向检查「每个 `*Routes.kt` 的入口函数都必须在 `Routes.kt` 的 `apiRoutes` 里挂载」和「装配点里的调用必须有对应文件」，扫描不到 ≥10 个入口即判据空转。这是 ARCHITECTURE §13#2「catalog 与运行时注册不绑定」的最小止血；运行期仍由 `RouteCatalogTest` 守。实跑 `./gradlew :app:test --tests 'io.legado.RouteMountTest'` → BUILD SUCCESSFUL（1m21s）。

## 3. 能不能在现有基础上做细节更改？——分三类

### 3.1 直接可做（低风险，收益确定）

1. **`lib/api.ts` 指路修正**：`:1-2` 的 `@deprecated` 指向 `lib/api/index.ts:60-63`，但那里不导出 `api` 对象，真正的组装点在 `lib/api.ts:53`；实测 65 个文件走兼容层、0 个文件走新入口、0 处 `api.sources.*`。把组装搬进 `lib/api/index.ts`、`api.ts` 降为一行 re-export，调用点零改动。这是「文档说的和代码做的相反」里最便宜的一处。
2. **`ReaderScreen` 首刀 A**：`handleSwitchSource` 1276–1519（244 行）→ `useReaderSourceSwitch`。它是最大块、耦合最低；验收：文件 ≤2,110 行、行为不变、`ReaderScreen` 相关 25 个测试文件不全红。
3. **`ShelfPage` 两个模态外移**：23–370 的 `BookInfoEditModal`/`BookManageModal` 全仓无外部 import（只在本文件 359/1184 内部用）。外移后 `ShelfPage.tsx` ~890 行、`export function` 计数=1，测试改动面小于阅读器。
4. **文档漂移与门禁**：本轮已校准 `docs/STATUS.md`、`product/docs/restructure/facts.md`、`AGENTS.md`、协议模板（`npm run protocol:sync` 后三份入口一致）、README 目录树、`contract.yml` 注释、`gates-guide.md`、`version-gate.yml` 路径；并补了路由挂载门禁。
5. **纯能力项**：M3 令牌补齐（只加 CSS 变量，不动结构，`styles.css:25-40` 现在只有 16 个令牌，缺 `surface-container*` / `outline-variant` / `inverse-*` / `primary-container`）；全书加权进度（纯函数 + 单测，见 §5 R1）。

### 3.2 需要前置条件（先降成本，再动）

1. **拆任何 hot 文件之前，先处理「测试钉源码文本」**：86/134 个前端测试文件、414 处 `readFileSync`（`ImmersiveDefault.test.ts:23,36`、`DragSortMath.test.ts:46,53`、`MobileSources.test.ts:57`、`CustomizeSkin.test.ts:437` 等）。测试引用 hot 文件的行数：`ReaderScreen` 25 文件/34 行、`SourcesPage` 11/20、`ShelfPage` 7/12、`api/types` 8/13。**结论：先建 `SourceTextReads` 基线（把「读源码断言」集中登记、只许减少），否则每拆一刀都要改一批测试，拆分收益被测试维护吃掉。**
2. **`RuleRunner` HTTP 段第二刀**：`fetchDetailedImpl`/`buildRequest`/`effectiveHeaders` 一带没有窄测试（B3），且要避开 `JsSandbox(this)` 的构造依赖。先补「请求构造 / header 合并 / 目标校验」的纯函数测试，再抽；靠 `GoldenRuleTest` 逐字节比对兜底。
3. **`RuleProcessor` 默认处理器注册**：扩展点 §0 已接、`GoldenRuleTest` 13 项绿，但生产 0 注册（dispatcher 空转，B4）。注册前先补「同一规则被两个处理器认领」的判据，否则等于给空转加一层壳。
4. **单写连接事务装置化**（B2）：12 个 DAO 手写 `autoCommit`，靠注释约束；`ReentrantLock` 可重入，嵌套 `write{}` 会静默破坏事务。先做「嵌套即抛」的开发期断言/装置，再谈迁移。

### 3.3 不建议做（ROI 低或有反例）

- **不要把 `types.ts` 按 domain 拆成 5 个文件**：实测 `types.ts` 是唯一类型源（86 导出），`domains/*` 的类型定义是 0；拆了只增加 import 路径，不减少耦合。
- **不要复活「统一出站层」**：ARCHITECTURE §13#3 已明确撤销；现在 6 处裸 `HttpClient`（B5）该做的是「收口到可注入的 client + 一条判据」，不是再盖一层抽象。
- **不要继续给插件 runtime 加功能**：`extensionRegistry.ts:28` 的 `registerExtension` 0 调用，`ExtensionSlot.tsx:30` 只有 `ReaderChrome.tsx:147` 一个挂点，`slotRegistry.ts:27-38` 声明 5 个 slot 永远渲染 fallback。要么删（推荐，先留 registry 接口），要么补真实调用方；不要第三种「再加一个 slot」。
- **不要大动 `JsSandbox`/`JavaPackages`**：Java 桥的回归成本远高于拆分收益，除非有明确的规则兼容 bug。
- **不要换状态库 / 换 CSS 方案 / 引入新依赖**：现有 node:test + Vite + 手写 CSS 的门禁链是通的；换栈会把 1,056 项前端测试和 1,109 项后端测试同时变成迁移成本。

## 5. 与 legado-with-MD3 的对标（含一个关键校正）

**校正**：`HapeLee/legado-with-MD3` 与 `legado` 上游同期分支基本同源。抽查 `Typography.kt`、`ThemeComponents.kt`、`HeuristicPageEstimator.kt`、`ReadBookScreen.kt`，`git diff --no-index -w` 零差异；两仓文件集同数（theme 35 / reader 114 / sheet 46 / pageestimate 8）。**所以「MD3 的做法」= legado 3.0 Android 的做法**，借的是能力模型，不是某个 fork 的私有实现。

legadoQ 并不缺阅读器大件：排版引擎、分页、TTS、笔记、皮肤、漫画、RSS、JVM 规则引擎、AI Agent/MCP 都有。缺的是「体验闭环」和「设计系统完整度」：

| # | 缺口 | legado 参照 | 移植难度 | 建议批次 |
|---|---|---|---|---|
| R1 | 全书页数 + 加权总进度（现在是章序号均分，`readerProgress.ts:41-44`） | `pageestimate/` 8 文件、`HeuristicPageEstimator.kt:9-20` | 中（纯函数 + 缓存） | 第 3 批 |
| R2 | 种子色派生皮肤（现在 `styles.css:72-78` 只有 7 套静态皮肤） | `ThemeEngine.kt:113-130` | 中（HSL 派生 + 对比度校验） | 第 3 批（可选） |
| R3 | M3 令牌补齐 | `styles.css:25-40` 仅 16 令牌；`ThemeEngine.kt:137-142` 的 `[data-amoled]` | 低（只加 CSS 变量） | 第 1 批 |
| R4 | 封面取色 | `ImageSeedColorExtractor.kt:28-40` | 中（Canvas 抽色 + 降级） | 第 3 批（可选） |
| R5 | 动画档位/速度/墨水屏 | 阅读器设置 | 低-中 | 按需 |
