## 0. 方法与可复现命令

```bash

sqlite3 "$DB" "select count(*) from source;"                     # 5600
```

注意两点，否则数字会翻好几倍：

- `grep -c '"preUpdateJs"'` 数的是「键存在」，导出包里大量 `""`/`null`。`preUpdateJs` 键出现 117 次，**非空只有 36 条**。

## 1. 字段级：存得下、可编辑、服务端零执行

这些字段在 `product/web/src/features/source-editor/bookSourceFields.ts` 里有表单项，导入/导出原样保留，后端 `product/app/src/main/kotlin` 全仓 grep 无执行点。

| 字段 | 非空条数 | 上游语义（clone 内证据） | 本服务端 |
|---|---:|---|---|
| `ruleToc.preUpdateJs` | **36**（其中 32 条调用 `java.refreshTocUrl()` 或 `java.reGetBook()`） | 更新目录前执行，可改 `book.tocUrl`；配套 `refreshTocUrl()`/`reGetBook()` 只在此时可用（`WebBook.kt:285-293`、`AnalyzeRule.kt:986/1011`） | 零执行。`refreshTocUrl`/`reGetBook` 也没有绑定 |
| `ruleToc.formatJs` | **6** | 章名/章址二次加工（`TocRule.kt:14`、`BookChapterList.kt:139-149`） | 零执行 |
| `concurrentRate` | **42** | 每源并发/间隔（`BaseSource.kt:68`、`BookSource.kt:59`） | 零执行；只有全局并发 |
| `ruleContent.webJs` | **8** | 交给 WebView 取正文（Android 侧） | N/A（无 WebView），但导入**不提示** |
| `ruleContent.sourceRegex` | **51** | 只在 `BackstageWebView` 用（`ContentRule.kt:18`、`BackstageWebView.kt:347`） | N/A（无 WebView），导入不提示 |

结论：`webJs` / `sourceRegex` 是**形态冲突**（要 WebView），不算缺口；`preUpdateJs` / `formatJs` / `concurrentRate` 是**静默忽略**，属于「存得下但跑不出」的一类，至少应在校验告警里说出来（编辑器「校验」走 `POST /api/sources/validate` → `scanIncompatibilities`；导入接口只回 errors，不带 warnings）。

## 2. JS API 级：`java.t2s` / `java.s2t` 缺失，正文会整章失败

上游确有这两个函数：`JsExtensions.kt:781`（`t2s`）、`RegexJsExtensions.kt:32`、`ChineseUtils.kt:14`；`s2t` 同源。本服务端 `rules/JsSandbox.kt` 的 `createJavaBridge`（`JsSandbox.kt:1136`）没有绑定，`grep -rn 't2s' product/app/src/main/kotlin` 为空。

使用面（sqlite 按段统计，允许同源多段）：

| API | 合计 | `ruleContent` | `ruleBookInfo` | `ruleSearch` | `ruleToc` | `ruleExplore` |
|---|---:|---:|---:|---:|---:|---:|
| `java.t2s` | 30 | **11** | 14 | 15 | 12 | 3 |
| `java.s2t` | 7 | 0 | 0 | 3 | 0 | 0 |

失败语义（不是「结果差一点」，是两种不同后果）：

- Rhino 里访问未定义属性返回 `undefined`，**调用**它抛 `TypeError`。
- `ruleBookInfo` 的每个字段都包在 `runCatching` 里（`RuleRunner.kt:662-684`），所以 `t2s` 只让**那一个字段为空**（作者/简介/最新章节丢失），书还能打开。
- `ruleContent.content` 没有包（`RuleRunner.kt:959` 直接 `root.value(...)`），异常一路上抛 → **整章正文取不到**。11 条正文用 `t2s` 的源正好落在这条路径上，用户看到的就是 0.2.42 新加的「换源 / 返回书架」兜底页。

复现样例（`@get:{a}` + `@js:` 包 `java.t2s(tzs(result))` 的写法，本机库里成批出现）：

```json
"ruleBookInfo": { "author": "@get:{a}\n@js:\njava.t2s(tzs(result)) ", "intro": "@get:{i}\n@js:\njava.t2s(tzs(result)) " }
```

落地成本的关键：**简繁表前端已经有了**。`product/web/src/features/reader/content/scriptConvert.ts` + `dict/openccData.ts`（OpenCC 数据，约 200 KB，按需 chunk）。服务端实现 `java.t2s` 可以直接复用同一份表生成 Kotlin 资源，不必另找词表；代价是常驻内存与包体，换来 30 条源（11 条正文级）可用。

## 3. 环境全局：`globalThis.environment` 缺失

1 条源（`蓝批小说（优+++）`，库内两行重复导入）在 `ruleContent.content` 里：

```js
function replaceNewPage(content) {
    if (!globalThis.environment.IS_LEGADO_SIGMA) { /* 自己替换 [newpage] */ }
    // Sigma 分支：保留标记，交给阅读器分页
}
```

`environment` 是本服务端与 gedoor 上游都没有的全局（legado-E / Sigma 扩展）。`globalThis.environment` 为 `undefined` → 取 `.IS_LEGADO_SIGMA` 抛 `TypeError` → 与上节同一条正文路径，整章失败。

补法极轻：沙箱里放一个只读常量对象 `{ IS_LEGADO_SIGMA: false }`，脚本就会走「非 Sigma」分支，自己把 `[newpage]` 替换掉。注意**不要**设成 true —— 那是让阅读器负责分页，我们没有这个契约。

## 4. 顺带核清的三个「看起来很大」的伪缺口

| 观察 | 实际 |
|---|---|
| `ruleReview` 命中 26 条 | 26 条全是 `"ruleReview": {}`，`detailListRule` **0 条**。C-03 的只读后端在现库里**一条也用不上**；再补阅读器浮层，收益为 0，优先级应下调到「等真有源再用」 |
| `eventListener` / `customButton` 各 5,524 条 | 源模板默认 `false`；`true` 各 **1** 条，且是 Android UI 行为，Web 无对应 |
| `@webjs:` / `showPhoto` / `onlyDisk` / `skipRateLimit` | `@webjs:` 0、`showPhoto` 0；`onlyDisk`、`skipRateLimit` 库内 0 但**已实现**（`ScriptCache.kt:65`、`JsSandbox.kt:1158`） |

## 5. 建议顺序（按「证据 × 成本」）

1. **校验告警补四项**（零行为风险，2026-11-13 已落地）：`preUpdateJs` / `formatJs` / `concurrentRate` 非空时在 `SourceCodec.scanIncompatibilities`（`SourceCodec.kt:188`）里说明「本服务端不执行」；`webJs` 与 `webView` 并列提示。现在这三种是纯静默，用户只会以为是自己源坏了。
2. **`java.t2s`（+`s2t`）**：唯一有正文级硬失败的缺口（11 条源）。复用前端 OpenCC 表生成资源，绑定到 `createJavaBridge`；判据可直接用库里两条真实源做金样本。
3. **`environment` 常量**：1 条源，几行代码，顺手。
4. **`preUpdateJs`**：36 条，但 32 条只是想刷新 `tocUrl`。动手前先确认「详情每次都取、`tocUrl` 已是最新」是否已覆盖其意图；否则要补的是「目录更新前重取详情」这条链路，而不是执行任意 JS。
5. **`formatJs` / `concurrentRate`**：6 / 42 条，收益偏小，排在兼容内核之后。
