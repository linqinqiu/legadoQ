# 更新日志

本文件记录「青阅」自身的变更。格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，
版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

版本号只有一个来源：`app/build.gradle` 里的 `version`。打 jar 时由 Gradle 写进清单的
`Implementation-Version`，服务端从清单读出来经 `/healthz` 报给界面，所以**构建产物、接口与顶栏显示的
是同一个数**。界面上不写死版本号。

这一份只写**用户能看见的变化**：一条一行，说清多了什么、修了什么。
「为什么这样做、量到了什么、哪条判据盯着它」不写在这里 —— 那些记在 `AGENTS.md`
（部落知识与工作记忆表）和 `docs/sessions/` 里。把工程日志写进更新日志，
使用者就找不到"这版对我有什么变化"了。

版本号用「小更新计数」（2026-10-12 起）：三段号 = 档位.小更新序号，每发一次小更新第三段 +1，满 10 进一次级（0.7.9 之后再发 → 0.8.0）；一版一条，不再按天合并。
**档位**指前两段（`0.8`）：破坏性变更（接口/数据格式/需要用户动手迁移）时第二段 +1、第三段清零；没有破坏性变更就只动第三段。

每个版本条目内的小节按这个**固定顺序**排，同名小节只许出现一次：
`### 新增` → `### 变更` → `### 修复` → `### 移除`。
新增放最前，是因为"这版给我多了什么"比"修了什么"更该先被看到。判据在 `web/test/Changelog.test.ts`，只盯当前版本那一条（历史条目不回头改）。
每条一句话、不超过一行（约 60 字）；实测数字、根因分析、环境变量名这类工程细节不进这里，记到 `docs/sessions/`。

## [0.8.7] - 2026-10-26

### 新增

- **启动时会核对"跑着的界面"是不是最新构建。** 不一致直接拒绝启动并告诉你该敲哪两条命令，不再出现"改了却看不到"。
- **探活接口报出当前界面的指纹与启动时刻。** 版本号相同、包却是旧的这种情况，现在一条命令就能分辨。

### 变更

- **界面资源改成压缩传输 + 长期缓存。** 第一次打开之后，重开几乎不用再下载那些文件，加载明显变快。
- **弹层打开时右下角的 AI 球自动让开。** 阅读设置、目录抽屉不再被它压住；球自己展开的助手面板不受影响。
- **窄屏下 AI 球与「安装到桌面」提示条抬到导航之上。** 手机底部那排入口不再被挡住。

### 修复

- **整库搜索时不再整页反复重绘。** 搜索越忙界面越卡的那一下，根源是主壳订阅了整份搜索状态；现在只订阅它真正要用的那一个开关。
- **书源页在手机上不再写"从左侧列表挑选书源"。** 窄屏是上下堆叠、没有左侧，改成"从上方列表挑选"。
- **翻页与换字号时不再重复拆解同一章正文。** 同一章内容改成本地取一次、之后复用。

### 移除

- **设置页的「界面偏好」分区。** 两个开关（浮动窗口默认钉住 / 默认收起）写下的值没有任何地方读取，描述的浮动窗口也早已不存在 —— 说谎的控件不如没有。

## [0.8.6] - 2026-10-24

### 新增

- **本机跑的模型能接进来了。** Ollama / LM Studio 只有回环地址可填，而闸门一刀切拒回环，等于这台软件只准接外网模型。设 `LEGADO_AI_ALLOW_LOOPBACK_BASEURL=1` 放行：只放回环，仍拒绝让 AI 打回服务自己（那会绕过它唯一的写保护）。
- **更新日志自动记。** 提交后自动把 feat / fix 提交补成当前版本的条目，漏记时 `npm test` 与 CI 会拦；细则见 `docs/changelog-guide.md`。
- **换源时可以指定书源和分组了。** 换源弹窗顶部多一条与搜索页同款的范围选择（全部书源 / 按分组 / 指定书源），不想让换源翻遍全库的时候能只在那几组里找。
- **应用名称和图标可以自定义了。** 设置 → 服务 → 应用名称与图标：改名后本机标签页、顶栏与装到桌面的应用都用这个名字，图标另收一张 PNG / JPEG / WebP（不收 SVG）。存的是本机安装根，不需要重新构建。
- **目录里读过的章节右侧显示字数。** 某一章的正文取到手之后，那一行右侧就不只是"能不能离线读"，还报出这一章有多少字。
- **加密过的书源能读了。** 一批漫画 / 聚合源把正文用 AES 加密后再塞进 JSON，规则里靠 `java.aesBase64DecodeToString` 解出来。以前这个函数不存在，书源直接取不到内容，报的却是「JSON 解析到一半结束」这种和真正原因无关的错。

### 变更

- **自定义皮肤多了一种语义：全权自定义。** 选它之后，这套皮肤只用你自己写的变量，没写到的不再沿用任何预设配色 —— 换内置皮肤不会带着它一起变。老的自定义皮肤照旧按从前的叠加方式工作，外观不变。
- **`plugins/` 目录里的 jar 默认不再自动装载。** 装载第三方 jar 等于在本机进程里执行任意代码，而这台服务不设身份；能读走你登记的模型密钥、能绕开护栏改库。工具、钩子、模型协议、连接策略这四个扩展点照旧全部可用，只是不再从磁盘吞 jar。确实要用的人设 `LEGADO_PLUGIN_JAR_SCAN=1` 打开；目录里有 jar 而没装载时，运行日志会写一句，不会静默。
- **阅读器去掉了手机样式的底部导航。** 那条五键底栏与底部动作排不再出现，桌面端动作都在顶栏，底部只留一条进度。

### 修复

- **漫画源能读正文了。** 正文清洗会把包在 `<div>` 里的整块内容一起删掉，而漫画站普遍每张图都包在一个 div 单元里 —— 于是一整章图片被连图带壳吃掉，界面报「正文规则未提取到内容」。现在图片保住、div 里的广告文字仍照旧丢弃。
- **点「同步到本设备」之后，已经缓存的章节不再重新长出小云朵。** 那一步原先用本机的下载记录整体替换了缓存标记，把只在服务端缓存过的章节全部误报成"未缓存"。
- **TXT 分章规则按浏览器直觉写的 `\s` 能认出全角空格缩进了。** Java 的 `\s` 只认 ASCII 空白，而中文 TXT 的章节标题普遍用全角空格缩进：`^\s*第\d+章` 在浏览器里能匹配、存进服务端就一条都命不中，整本书切不出章，界面上却写着"已保存"。
- **新建的 TXT 分章规则能真的被自动选中了。** 自建规则必定排在表尾，而自动打分命中够多就提前定案 —— 长篇书在前面几条随包规则就凑满了，你新建那条永远轮不上，看起来"规则不生效"。
- **AI 连接填了内网 / 本机地址不再报"服务器内部错误"。** 从前返回 500 加一句 `AI 请求失败：invalid_request`，人只会去翻服务端日志；现在返回 400 并把闸门那句原话带回界面上。
- **域名打错一个字母不再被说成"请求非法"。** 解析不了如实报 502 + "无法解析 xxx 域名"；且同一个坏地址在「对话」与「阅读理解」两条路径上前者报 500、后者报 502，现在两条一致。
- **开阅读器后新读到的章节会即时熄掉小云朵。** 服务端在你读正文时已把它缓存下来，但界面只在开阅读器那一拍拉一次标记，读着读着云还挂着。
- **本书内搜索不再一按就报错。** 检索在缓存正文表里查了一个并不存在的章号列，空库看不出来、真缓存过正文就抛错；现在章号随正文一起落库，老库启动时按目录回填。
- **设置页搜索不再漏掉长关键词。** 曾经「查询超过 5 个字就不算命中」，理由是躲一行并不存在的「登录」入口；「替换净化规则」这类真词全被挡成空结果，现恢复全文匹配。
- **AI 净化 / 润色的「保存」与「撤销」两条接口终于真的能用了。** 它们被写进了另一个接口的处理器里，启动时没有注册，请求一律 404 —— 也就是说 AI 覆盖正文存不进去、也撤不掉，界面却像是调通了。
- **别的网页再也不能偷偷替你建朗读会话了。** 防跨站写入的那道闸门原来是每条接口自己记得调一次，朗读会话的三条写接口整条漏了：任何网页都能替你在本机建会话、追加音频、改播放状态。现在闸门改成全局生效，新接口默认就在保护之下。
- **想把服务开到局域网的，现在必须先明说一声。** 这台服务没有账号也没有密码，绑到 `0.0.0.0` 就等于把整个书库（含按域共享的登录凭据）交给局域网，而以前只要改一个环境变量就能悄悄做到。现在启动时直接拒绝，确实要对外（比如容器部署）得显式设 `LEGADO_ALLOW_EXTERNAL_BIND=1`，启动日志会留一条警告。
- **接口类书源搜索不再凭空返回 0 条。** 书源规则里 `bookList: list` 这种不带 `$.` 的写法很常见（字段一向支持，列表这一路却漏了），它被当成了网页选择器，于是一条都选不中；站点本身好得很，界面上只有一句"一条都没有"。
- **电脑上读书不再冒出一条手机导航栏。** 阅读器的工具栏一唤出，底部会出现一排手机味的功能条（目录 / 搜书 / 笔记 / 朗读 / 设置 / 沉浸），而这些按钮顶栏本来全都有。现在宽屏下底部只留「上一章 / 进度 / 下一章」，窄屏（手机、半屏小窗）仍是原来那条。
- **书源链接后面带请求参数时，逗号后多打个空格也能认了。** 以前只认「逗号紧贴花括号」，写成 `地址 , {"method":"POST"}` 就整串被当成网址，请求直接失败；现在和上游一致，逗号前后留空白都认。
- **一批加密/接口类漫画源现在能读到正文了。** 这类书源在「书籍信息」里存一个内部编号、到「目录」再取出来用，我们原来只把搜索时存的编号带过去，书籍信息里新存的那个到不了目录，于是章节地址拼出一串空参数、上游直接报错。现在两个阶段的编号都能传给后面。

## [0.8.5] - 2026-10-23

### 新增

- **AI 悬浮球能拖到顺手的位置了。** 位置会记住，下次打开还在原地，也不会被拖出屏幕边缘。
- **悬浮球可以隐藏。** 隐藏后在屏幕边缘留一个很小的恢复把手，不会找不回来。
- **悬浮球会显示连接状态。** 没接模型是灰红点，接了是绿点，不用点开就知道能不能用。
- **AI 对话可以同时开多个。** 面板顶部能新建、切换、删除会话，双击改名；
  以前的单条对话会自动迁移，历史不会丢。
- **AI 有了预设人设。** 通用 / 小说助手 / 书源调试 / 代码解释，点一下切换，
  不用每次重写系统提示词。
- **AI 接入面板能看到每个工具从哪来。** 内置的与插件注册的分开列，
  便于判断某个能力是不是插件给的。
- **目录顶端可以直接加书架。** 已在书架里的书显示「移出书架」。

### 变更

- **AI 密钥输入框改成密码框。** 输入时不再明文显示，避免旁人一眼看全。
- **`/api/catalog` 报的地址跟着实际端口走。** 以前固定写 1234，用别的端口启动会把外部调用方
  指错；现在返回当前进程真正监听的 `host:port`。

### 修复

- **iPhone 加到主屏幕的图标不再是空的了。** 那张 180×180 的图标以前只剩绿底和右下角半个白边，
  书本图案根本没在画面里；现在换成完整图案，四角不透明（圆角交给 iOS 自己切）。
- **安装后的应用语言被标成了英文。** 应用清单里的 `lang` 一直是默认的 `en`，与中文界面对不上；
  现在明确写成 `zh-CN`。
- **快捷方式菜单的图标发虚。** 「我的书架 / 书源管理 / 替换净化」三项的图标原先只有 48×48，
  高分屏下糊；现在统一 96×96。已安装的应用下次打开时会自动更新，不用重装。
- **目录固定到侧栏后，标题栏不再挤成一列。** 侧栏窄的时候，「目录」两个字曾被挤成竖排，
  六颗按钮还会溢出到正文上；现在标题永不换行，按钮放不下时整排换到第二行，都留在侧栏里。
- **抽屉打开时，顶栏的书名不再被切掉一半。** 书名是整屏居中的，抽屉盖上去正好压住它；
  现在抽屉打开时收起书名（抽屉自己写着「正在读：第几章」），顶栏也补了上边距，不再贴着窗口沿。

## [0.8.4] - 2026-10-21

### 新增

- **AI 看得见你选中了哪一段了。** 在正文里划出一段文字，AI 助手就知道你正盯着哪句话、
  在第几章 —— 问「这段什么意思」问的就是眼前这段，不再是泛泛谈整章。
  助手面板上会显示「选中的 N 字」，不让这件事变成黑箱。
  选区有长度上限：整章那么长的选中不会一次塞进请求。
- **AI 能整理你的书架了。** 新增书籍分组的列出/新建/删除/归组，
  以及阅读进度的保存 —— 以前这些能力接口都有，AI 却够不着。
- **AI 多了三个阅读侧动作。** 对选中的文字做净化（去广告、去乱码）、
  改写（润色、生成朗读稿）、以及保存为高亮或笔记。
  净化走的是与正文同一套净化器，不是另写一份规则。
- **AI 会记下读到哪了。** 新增阅读进度写入，模型改完书单后能把进度一并记下。
- **AI 能听、能看备份了。** 新增朗读音色列表与文字合成、备份区条目列出与读取。
  音频本身不进模型上下文（二进制进去只会把上下文撑爆），只回字节数与参数。
  这两类能力在服务没接上时**如实说不可用**，不会假装成功。
- **第一个插件能跑起来了。** `examples/plugin-hello` 是一个真的能编译、能装载、
  能被 AI 调用的最小插件（8 KB），带一份把四个实测坑写清楚的说明：
  Kotlin 版本要对齐、依赖必须 `compileOnly`、`io.legado.data` 的方法是顶层扩展函数要显式 import、
  jar 运行期被占用删不掉。装上后 `/api/plugins` 从 `loaded:0` 变成 `loaded:1`。
- **划线笔记能带走了。** 阅读器的「笔记」面板里多了一个「导出 Markdown」：
  整本书的划线按章节顺序排成一份文件，原文进引用块、备注跟在下面，章名取不到时
  退回「第 N 章」而不是编一个。以前这些划线只能一条条看，想拿去写读后感或丢进
  别的笔记软件没有出路。导出是纯前端动作，不新增端点。


- **体检结论落库了，搜索按它排先后。** 以前跑一场几十分钟的体检，结论只存在浏览器
  localStorage 里，服务端看不到 —— 而最该用它的搜索恰恰拿不到。现在体检完写进
  `source_health` 表，同步搜索按「能用的在前、快的在前」发车：截止时间不变，
  但同样的时间先撞上的是好源。没体检过的源排在后面，且保持原有顺序
  （"没体检"不是"不能用"）。
- **AI 能调用的每个工具都标了是谁装的。** 以前 `/api/agent/manifest` 只回
  `id/group/description/writes`，插件一多「AI 能调 56 个工具」就成了黑话：
  想卸一个插件时无从判断会影响哪些能力，某个工具行为怪异也分不清是谁装的。
  现在每条工具带 `origin`（`builtin` 或 `plugin:<插件id>`），
  卸载插件也改成按来源索引精确摘除 —— 不碰内置、不碰别人的。
- **工具轮数与数据上限可以调了。** 原来 `MAX_TOOL_ROUNDS=6`、`MAX_TOOL_DATA=4000`
  写死在 `Agent` 里。现在走 `LEGADO_AI_MAX_TOOL_ROUNDS` / `LEGADO_AI_MAX_TOOL_DATA`，
  默认值与从前一致。调到可配置主要不是为了"能改大"，而是为了**能改小**：
  接的模型很笨时会反复调同一个工具，把一次对话拖成十几次外呼。

- **Docker 镜像又能构建了。** 上一版把后端目录从 `server/` 改名为 `app/` 时漏改了 `Dockerfile`
  里的构建命令与 jar 路径，`docker build` 会直接失败。现已对齐：`:app:installDist`、
  `app/build/install/legado/lib/legado-*.jar`、`/app/bin/legado`。
- **`npm run coverage` 又能用了。** 同一个改名漏掉了覆盖率报告的读取路径与 Gradle 任务名，
  命令会报错。现已指向 `app/build/reports/jacoco/...` 与 `:app:testCoverageReport`。
- **漫画源又能用了。** 漫画阅读依赖一个漫画图片代理页 `manga.html`，但书源下发时只给了 `url`、
  没下发代理地址，前端拿不到代理导致漫画源打不开。现已给每个漫画源补上 `Reload(url)` 全局，
  传进真实代理地址，漫画源恢复正常。
- **书源体检能比出「结论变了」。** 重测时体检结果现在会和上一次基线（同会话或 localStorage 里
  跨会话保存的那份）逐源比对，完成提示会多一句「对比上一轮体检，N 个源结论变了（其中 M 个变差）」，
  弹窗里也有一条变化提示。仅比结论档位（好 / 待确认 / 未配搜索 / 异常），同一档位内的细分
  （如能搜到、慢）不算变；新出现的源不算变。自动打标仍只动「异常 / 待确认」两档，不改启用状态、
  不改用户自己写的分组标签。


- **AI 助手常驻右下角，任何页面都能问。** 以前 AI 只能从「设置 → AI 接入」打开一个弹窗，
  人得离开正在看的书或书源、走三层才能问一句。现在右下角有一颗悬浮球：点开就是对话面板，
  切页面、关掉再开都不丢；它知道你在哪个页面、在看哪本书的第几章、选中了哪个书源。
  对话历史跨页面、跨会话保留（存本机），也可以随时清空。
- **AI 补上了三个阅读侧能力。** 现在能按书源取**书籍详情**（书名/作者/简介/封面/目录地址）、
  按 `sourceId + bookUrl` 取**书架里单本书**（含阅读进度）、单独取**阅读进度**（读到第几章）。
  以前问"这本书讲什么""我上次读到哪"时，它只能把整份书架拉回来自己猜。

### 变更

- **接口文档里的 query 与请求体参数说明补全了。** `docs/API-REFERENCE.md` 里有 89 处
  `[object Object]` —— 该显示「`q`=可选：按名称或地址子串筛」的地方只显示了一句
  JavaScript 的对象占位符，接进来的人根本不知道该传什么。现已由随包的端点契约

  （`.bat` / `.cmd`）保留 CRLF，图片与 jar 等二进制不做转换。此前同一份文件在 Windows 与
  Linux 之间检出会整篇翻转，diff 里看不出真正改了什么。

  页头与编辑器，不再被订阅面板撑长。

### 修复

- **AI 连接的地址不许再指向内网了。** `baseUrl` 是用户自己填的，而 AI 这一层以前
  **没有过出站闸门** —— 书源、订阅、朗读的外呼都过，只有 AI 外呼没过。
  填一个内网地址，这台机器上的其它本机服务（路由器管理页、数据库、另一个本地端口）
  就会被这个 AI 连接打通。现在复用与书源同一道闸门（IPv4/IPv6/组播/保留段/CGNAT
  都已覆盖），内网地址直接拒绝，并明确告知「这是地址问题」而不是笼统的「连不上」。
- **「全部书源」搜索不再把请求挂死。** 库里 5598 个启用书源时，一次「全部书源」搜索
  实测要 25 分钟以上（单源并发 16~32、单源超时 30 秒），脚本与自检在 300 秒处就断了 ——
  不是报错，是**真没返回**。
  根因不在并发：取值链路用的是阻塞式 HTTP 调用，它不响应线程中断，
  外面那层「单源 30 秒超时」取消不掉卡在网络上的任务，慢站会一直占着并发名额。
  现在给同步搜索加了**总量截止**（默认 60 秒，`LEGADO_SEARCH_TOTAL_TIMEOUT_MS` 可调）：
  到点就返回**已经搜到的部分**，不再无限期挂着。实测全库搜索 61.6 秒返回 1098 条结果。
  截断不静默：响应头 `X-Search-Truncated` / `X-Search-Completed` / `X-Search-Total`
  如实说明搜了多少个源，调用方分得清「就这么多结果」与「没搜完」。

- **阅读器里也有 AI 助手了。** 以前 AI 悬浮球只挂在主界面上，而阅读器是另一层独立外壳
  （它自己那层 app-shell），于是读到一半的正文里根本没有 AI 入口 ——
  「不能随时随地使用、不能在对应地点研究」在最该用的地方不成立。
  现在阅读器里也常驻那颗球，且它带的是「正在读这本书第几章」，
  问的就是眼前这一段。
- **AI 面板的宽度按设计走了。** 面板原先声明 420px 宽，但被共用的弹窗外壳
  静默覆盖成 680px，实测宽出来的 260px 白占了屏幕。现在交给弹窗自己的档位统一给。
- **弹窗开着时 AI 球不再压在弹窗上面。** 球的层级原先高于弹窗遮罩，
  模态弹窗打开后球仍浮在最上层、挡着弹窗。现在球在遮罩之下，与界面上的说明一致。
- **几处样式声明不再白写。** 有三处引用了样式表里并不存在的颜色/字号变量，
  浏览器解析不了就把整条声明作废（文字颜色落回继承）。现已指向真实存在的变量。

## [0.8.2] - 2026-10-19

### 修复

- **列表规则里的 `&&` 与 `%%` 现在按 Legado 语义解析。** 以前只认 `||`，`&&` 那串被整条当成一个
  CSS 选择器，站点回 `SelectorParseException`、该源搜索/目录一条都没有（极速漫画就是这么坏的）。
  现在 `&&` 取各支并集、`%%` 按位交错、`||` 仍取第一个有结果的。
- **列表规则里的 `@tag.` / `@id.` / `@children` 方言段能用了。** 以前这些段被当成标签名拼进 CSS，

  2,164 条带 `tag.`、1,063 条带 `id.`、30 条带 `children`。
- **列表规则里的「分段级区间下标」现在认了。** 写法如 `class.foo.0:1:2`、`tag.div.-1:10:2`
  （步长可缺省），以前整段被丢进 CSS 选择器 ⇒ `SelectorParseException`，带这种写法的源
  一条都搜不出（豆花文学 `kind:.book_tag.0:1:2@text` 就是这么坏的）。
- **字段选择器写坏不再拖垮整次搜索。** 某条字段规则解析失败时只让该字段留空、其余字段照常，
  而不是整条搜索抛 `SelectorParseException` 归零。

### 变更

- 列表（`bookList`）级写坏的选择器仍然**报错**（带 `SelectorParseException` 原文），

### 修复

- **删除书源后列表不刷新**：删除走了写入路径却没有失效书源清单缓存，界面会出现"删了还显示"，直到下一次写入才消失。缓存失效补上（E2E 场景 5 的计数断言在 CI 上逮到的）。
- **平移分页跨章时"同一栏看两遍 / 眼前内容滑走"**：每一章占几栏被首行缩进数多了（一章 8 栏数成 13），该垫的章末空白没垫出来，往回翻接上一章时页码落点差半栏。现在按栏宽分桶数栏，垫栏与页码补偿都对得上（翻页连续性门禁 19 项全过，新增接章前后几何转储判据）。
- **异常 EPUB 不再能把服务卡死**：导入 EPUB 时给解压加了三道闸（单个文件 64 MiB、整包 512 MiB、
  条目数 1 万），超了直接拒绝并报错 —— 以前一个几百 KB 的「压缩炸弹」能解出几十 GB 把内存打爆。
- **非文本章节不再被朗读**：音频 / 视频 / 文件章节的「正文」是一串媒体地址，点朗读只会把它念出来 ——
  现在这类章节的朗读入口是灰的，正在朗读时切到这类章节会自动停掉。
- **离线缓存漫画时把图一起存下来**：以前离线缓存只存正文（`![图片](url)` 占位行），离线打开漫画是一排
  裂图；现在缓存每一话时顺带把这一话的图抓进磁盘缓存（每话封顶 80 张），离线打开就有图。
- **有些书源的搜索 / 详情取不到东西**：两个都出在请求头上。① 书源 `header` 里写 `Connection:
  keep-alive` 很常见，Java 的 HTTP 客户端把它当**受限头**直接报错，搜索整条链路作废；② 书源自带
  User-Agent 时我们又在后面追加了一个，两个 UA 一起发出去、站点按第一个判 —— 详情接口因此返回空数据
  （搜索却正常，极易误判成"书源坏了"）。现在受限头过滤掉、User-Agent 让书源优先。
- **分页目录只取到第一页**：`nextTocUrl` 用 JS 拼出分页地址列表时（如懒人听书），返回的是一行
  JSON 数组 `["…","…"]`；原来只按换行拆，整个数组被当成**一个**地址去请求 → 报「URL 格式无效」、
  整本目录取不到。现在 JSON 数组也逐项展开（实测懒人听书目录 1645 章）。

  才高亮（95 条路径不再齐喊），「必填」徽章改轻量描边，分栏改胶囊样式，每个分组标题右侧
  新增完成度微条 —— 收起状态下扫一眼就知道每组填到几分之几。
- **目录预览一次全给**：原来只显示前 16 章、下面一条「继续展开」，五千章的书要点十几次；
  现在打开详情就把整份目录挂出来（离屏的行不参与布局，不会因此变卡）。
- **发现页「N 本书」计数挪到分栏行右端**：原来挂在结果表头，离分栏隔着一屏；现在选了哪个
  分栏、这个分栏几本书，一眼看全。

### 变更

- **CDS 归档过期时改成自动重建**：启动器发现归档比 jar 旧（比如刚重建过 jar、忘了跑 `make-cds.mjs`）时，
  这次照常启动（只是没享受到那几秒），同时在**后台**把归档重建好 —— 下次启动就快了。
  也就是说，重建 jar 之后**不必再手动跑 `make-cds.mjs`**（想手动跑也可以，见 README）。
- **打开更快**：给服务加了一份 CDS 类归档（`tools/make-cds.mjs` 生成，`start.mjs` 自动带上）——
  冷启动从 ~7.8 秒降到 ~4.8 秒（那几秒基本都是 31MB 打包 jar 的类加载）。重建 jar 后跑一次
  `node tools/make-cds.mjs` 重新生成即可。
- 删掉两句「解释界面自己」的话：发现页取源失败时那句「下面显示 0 个不是"没有书源"，是这一次请求失败了」，
  和运行日志取失败时那句「这不是"没有日志"，是这一屏没拿到数据」。取失败就说"没取到"——
  界面已经用「没取到书源列表」「没取到」说清了，不必再解释它跟"空"的区别。
- **「书源」回到顶栏**：书源管理重新是顶栏一级入口（排在「书架」与「发现」之间），不必再先进「设置」。
  「设置」页里那一行随之撤掉 —— 同一个目的地只留一条路。

### 修复

- **漫画 / 聚合源的目录取不到（0 章）**：这类书源把标识（如漫画的 `comic_id`）在**搜索 / 发现**那一次
  用 `@put:{bid:…}` 存下，目录与正文再 `@get:{bid}` 取。我们的 `@put` 变量原来只活在单次解析里，
  搜索一结束就没了 —— 现在按书留一份，详情 / 目录 / 正文都还取得到。
- **`tocUrl` 写成字面量地址时被当成选择器**：`tocUrl` / `chapterUrl` 常直接写
  `https://…/api?bid=@get:{bid}`，HTML 模式下被当成 CSS 属性名去取 → 取空 → 目录回落成书页地址。
  现在以 `http(s)://` 开头的规则按字面量地址处理。
- **漫画源的图整章变成乱码**：漫画源把 `<img src="地址,{"headers":"…"}">` 整串塞进 `src`（里面的引号
  没转义），旧的取图正则从 `src="` 取到第一个引号就停 —— 地址被截成 `地址,{`，标签后半截还留在正文里
  当文字排出来。现在按**整个标签**匹配、并剥掉 Legado 的 `,{…}` 图片选项。实测爱看漫画的章节正文
  已是干净的一行行图片（图片本身不需要 Referer，地址里的 auth_key 就够）。
- **书源简介漏出替换指令**：有些书源把简介写成「文字模板 + 尾部 `##正则##替换##`」（00小说网就是
  这样），整条当纯文本渲染时，替换指令原文会跟着简介一起显示（`…##(^|[。！？……；]+…)##$1<br>`）。
  现在先求值主规则、再对结果做替换。
- **简介里的 `<br>` 与换行被压成一行**：书源用 `<br>` 断句，界面按纯文本渲染时把它当字面量排了
  出来。现在 `<br>` 换成换行、其余排版标签去掉，简介按书源本意分段显示。
- 备份页「这个包会恢复什么」里「TXT 分章规则」被列了两遍（一条说"可套用到本机规则表"、
  一条说"原样存着、不读包里的这一份"，互相矛盾）—— 去掉过时的那条，只留说清下落的。
- **发现页分栏分隔符补齐 `&&`**（对齐 legado-with-MD3 的 exploreKinds 解析）：实测 110 个源的
  发现地址用 `&&` 分隔各分栏，原来只按行切，这些源的全部分栏被并成一条。RSS 订阅源的
  `&#` 分隔同时保留。
- **同源闸门补上 DNS 重绑定的洞**：原来拿 Origin 和请求自己的 `Host` 头互比，重绑定攻击下
  两者同为攻击域名必然相等、直接放行；现在比对的是**服务真实绑定的身份**（回环 / 配置地址 /
  绑全部网卡时的局域网私有 IP），公网域名无论解析到哪都过不了。
- **净化规则导入的远端拉取**：不再每次请求新建一个连接器（也不泄漏），补上读超时，
  `{"url": …}` 层层指向上一个的跟随链加了深度上限。
- **封面抓取改为边读边限**：恶意上游回一个巨大响应体时，原来整包读进内存之后才查 5 MiB
  上限；同时落盘改为原子替换，并发首取不会互相覆盖出半截图片。
- **阅读进度不再双写**：原来每次存进度都"入队 → 直写 → 再 flush 一遍刚入队的"，等于每
  1~2 秒两次网络写；现在只有直写失败才进离线队列补发。
- 书籍详情的换源体检不再因数据刷新被反复中止重启（重新联网复检所有源）；
  换书时上一本累积的封面报错计数会复位，否则下一本的有效封面显示不出来；
  阅读器里加架/移出书架失败不再无声无息；阅读器预载章节缓存加上限不再无限增长。
- **部分书源的简介 / 分类取不到**（实测 65 个源、00小说网发现页 30/30 全空）：两层根因。
  ① 书源模板常写 `{{@@#bookIntro@text}}`、`{{@@td.0@text}}` 这种 `@@` 开头的 `{{}}`，
  `@@` 只是标记、不是选择器的一部分，原来整串拿去当选择器，取值必空；
  ② 更根本的：`{{}}` 展开出来的结果原来会被**再当一次选择器求值**，纯文本拿去跑 CSS
  必空 —— 现在按上游语义，规则里出现 `{{}}` 就当文本模板，展开结果直接生效
  （00小说网发现页分类复测 30/30 取到）。
- **发现页（和搜索）的封面几乎都不显示**：书源规则常写成
  `a.0@href##book\/(.*)\/##https://站点/img/$1.jpg` —— 正则从 `book` 开始匹配、**吃不掉 href
  前面那个 `/`**，值就成了 `/https://站点/img/x.jpg`；我们随后把它当"根相对路径"去拼绝对地址，
  拼成了 `https://站点/https://站点/img/x.jpg`，浏览器根本加载不了（实测 00小说网 **30/30 全废**）。
  现在先看"去掉前导斜杠后是不是已经是绝对地址"，是就原样用（`/img/x.jpg` 与 `//cdn/x.jpg` 不受影响）。
- **手机上「安装到桌面」那条横幅横向溢出屏幕**：390 宽实测横幅自己是 358px，里面那句
  不换行的说明却把它撑到 507px（伸到屏幕外），7 张页面都中。根因是弹性布局的子项默认
  `min-width: auto`，被不换行的文案顶成内容宽；补上收缩后回到横幅内，超出部分走省略号。
- 桌面启动器（`start.cmd`）以前读了 `port.txt`，却**没把端口传给服务** —— 探活探的是新端口、
  服务还起在旧端口上，结果是"等半天等不到"。现在两边用同一个端口。
- **桌面那个「青阅」图标不会启动服务**：它其实是 Chrome 的 PWA 快捷方式 —— 服务没跑时点它，
  界面壳从缓存里出来后就一直等，要等满一分钟才放行。新增同目录的 `start.cmd` 启动器：
  服务没跑就把它起起来（后台、不占窗口），等真的能答了再打开界面；已经在跑就直接开界面。
- 加载页等十几秒后给一句能照着做的提示（告诉你去把服务启动起来），不再让人对着干等。
- **打开要等很久**（「正在打开阅读空间…」转半分钟）。两处一起改：
  ① **服务启动不再等后台的活儿** —— 订阅同步、缓存续跑、封面回收都挪到服务能连之后再做，
  先把端口让出来（实测端口就绪 ~10.7s → ~8.1s）。
  ② **界面不再等整份书源清单**（5,574 个源、约 1MB）才显示 —— 探活一过就进界面，书源在后台接着取。
  探活本身也加了超时：服务还没开始答话时能正常重试，并给出「正在等待本机服务启动…」的提示
  （原来那次探活会一直挂着，连提示都换不出来）。
- 加载页加了一个转圈：等十几秒时看得出"在动"，不再是一行字像卡死。

本版是**全库源码审查的自主优化**（两路独立审查 + 逐条核实），只收行为不变或更安全的修复。

- **「关于」页把别人的仓库当成开发者**：仓库地址的兜底值硬写着 `lukelzlz/legado`（这份代码当初 clone 来的地方），于是「开发者」「项目主页」「检查更新」三处都指向了不是你的名字。现在没配置就直说「未配置仓库地址」，不替任何人署名；要接上你自己的仓库，设环境变量 `LEGADO_REPO=你的用户名/仓库名` 即可。
- **「检查更新」从来没成功过**：请求头 `User-Agent` 拼的是应用显示名（`青阅/0.6.3`），而 JDK 的 HTTP 客户端在建请求时就拒掉非 ASCII 的头值 —— 那段又写在异常兜底之外，所以接口每次回 500，界面上念成「检查请求没有发出去」。现在头值只用 ASCII，且建请求也进兜底：真出问题时给的是原因，不是一个 500。
- **开源许可那一栏说了假话**：写着"借鉴设计，未拷代码"，而随包的 TXT 分章规则表 26 条与上游那份是**逐字节相同**的副本。同协议（GPL-3.0）分发本身没问题，瞒着不说才是问题 —— 现在这一栏把它认下来，标题也改成「语义参照与随包的上游数据」。
- **内置浏览器登录抓不到 cookie 的根因**：站点的登录请求走 `fetch` / `XHR` 时（SPA 基本都是这样），代理这一格只认 GET —— 那一次 POST 直接 404，请求根本没被发出去，`Set-Cookie` 自然吸不到。表现就是"有的源能登录、有的怎么试都不行"（表单提交那条路一直是通的）。现在子资源与站点自己发的请求共用一个口，GET / POST / PUT / PATCH / DELETE 都转。
- 抓取成功与失败现在都往运行日志记一条（哪个域名、几条）。原来异常被静默吞掉，界面上"没抓到"和"站点压根没发 cookie"长得一模一样，用户只能反复试。
- **往回翻不再丢位置**。原来翻页模式往回翻到窗口第一页时是"换一章重新锚定 + 跳到它最后一页"，而最后一页是按**当时的**页数算的（后面几章还没挂上来），实测落到上一章的中间（`4/15`，而那一章占 1–8 页）。现在改成与前进对称：把上一章**接到窗口前面**、页码整体后移它的页数，眼前这一页一个字都不动。
- **右键点正文不再把页面挪走**。翻页的点击判定没区分鼠标按键，右键也走"上/中/下"三区 —— 叫出菜单再取消，页面已经往上滚了一屏（翻页模式则是翻过一页）。
- **TXT 分章不再把标题的字漏进正文**。标题显示时去掉前后空白是对的，但正文起点原来按去掉之后的长度推算，差几个空白字符就有几个字从标题漏进正文；实测每章开头都多出标题的最后 1–4 个字。
- 翻页模式下框选文字时，左栏那颗「把选中 N 段加入书签」一直是灰的（选区只在滚动模式的容器里找）。

### 测试

- 新增浮层并档判据：样式表里声明"外壳几何"的类只许 `.dialog-shell` 一档、遮罩只许两条、
  关闭键只许一颗；每个弹窗挡片都必须套 `.dialog-shell`、接 Esc、有 `role="dialog"` 与名字，
  而且不许再用行内样式压宽高。四条注入反扫：故意加第 17 套外壳 / 第三条遮罩 / 第二颗关闭键 /
  一处行内宽高，判据必须各自报红。
- 门禁跟着改口的选择器：`.modal-backdrop` → `.overlay-backdrop`、四颗旧关闭键名 → `.overlay-close`、
  内置浏览器挡片 → `.overlay-backdrop.is-flush`。并档后没有样式的 11 个页面类名（门禁靠它们
  定位"是哪一张弹窗"）进了标记类白名单，每条写清是谁在引。
