# 端口与用户配置复查

## 背景与目标

用户提出：确认「更改端口」不会影响用户自己的配置，同时找细节层面的错误、优化仓库结构与内容框架。

目标不是读一遍代码点头，而是给出**能复现的证据**：换端口之后偏好还在不在、在哪落盘、哪些东西按设计就不跟着走。

## 核验发现

**1. 配置不受端口影响（实测，不是推断）**

```bash
curl -X PUT -H 'Origin: http://127.0.0.1:12346' -H 'Content-Type: application/json' \
     --data '{"kind":"none","palette":"violet"}' http://127.0.0.1:12346/api/ui-prefs/wallpaper   # 204
node stop.mjs && LEGADO_DATA_DIR=... node start.mjs --port 12347 --no-open
curl http://127.0.0.1:12347/api/ui-prefs
# → {"prefs":{"wallpaper":{"kind":"none","palette":"violet"}}}
```

落盘在 `<数据目录>/ui-prefs.json`，跟着数据目录走。浏览器侧由 `lib/uiPrefs.ts` 在 React 渲染前补回 localStorage，
所以换端口也不会出现「先按默认画一帧、再跳成用户设置」的闪动。收录 10 个键（免责声明 / 壁纸 / 阅读设置 / 书架与搜索布局 /
排序 / 侧栏宽度 / 朗读条位置 / 搜索历史 / PWA 提示），收录口径写在那份文件顶部。

**2. `port.txt` 写不进只读目录时，整个启动被打断**（`DesktopLauncher.shiftToFreePort`）

端口被别的程序占用会顺延，并把新端口写回 `port.txt`。数据目录有 `chooseDataDir` 兜底（Program Files 只读时退回
`%LOCALAPPDATA%`），**这行 `writeText` 没有**：只读安装目录下抛 IOException，直接打断 main。用户看到的是「双击没反应」。

**3. `.env` 里改的端口被 `port.txt` 静默盖掉**

优先级 `port.txt` > `.env`/环境变量 > 1234 本身合理（界面里改的端口不该被旧 `.env` 盖回去），但两者不一致时一句话都不说。
用户改完 `.env` 重启，端口没变，日志只有「启动中 http://…:旧端口」，猜不出原因。

**4. 三份手写文档的端点数停在 165**

`docs/API-REFERENCE.md` 是脚本生成的所以永远准；`ARCHITECTURE.md`（3 处）/`STATUS.md`（2 处）/`ROADMAP.md`（1 处）是手写的。
加完 `GET /api/backup/export` 之后没人回头改，三份一起停在 165，分组表里「备份 5」也少一条。

**5. 内容框架复查**

`docs/README.md` 是唯一入口，且刻意不逐条列 `docs/sessions/` 的文件（避免二次维护漂移）——这点是对的，不用改。
`docs/sessions/README.md` 规定了六节骨架；本文件第一版没照骨架写，已按骨架重排（就是现在这份）。

## 决策与取舍

- **不改端口优先级**：若让 `.env` 压过 `port.txt`，界面里改的端口下次启动会被 `.env` 旧值盖回去 —— 那个方向更糟。
  选择「保留优先级 + 日志明说」，把困惑消掉而不移动坑。
- **`port.txt` 写失败不拦启动**：记住端口是便利，不是功能。写不进去就照常起在空闲端口上，代价只是下次再探一遍。
- **端点数门禁收窄口径**：只认「端点数：N」「N 条端点」「N 条 / M 组」「当前返回 N 条」「端点分布（N 条」这几种
  「看起来在说总数」的写法；「AI 22 个端点」这类分组内数字不纳入，否则第一天就会满屏误报。
- **壁纸图片不搬服务端**：体积与既有 IndexedDB 分工都不支持，只同步设置。
