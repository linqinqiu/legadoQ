# 地址脚本、jsLib 方言与请求头编码（0.2.10）

## 背景与目标

按书源类型继续做 live 抽检时，搜索/详情阶段的报错集中在地址与脚本装配这条链上：

1. **地址里的 JS** —— 规则形如 `@js:...`、`<js>...</js>`，或地址尾巴再拼 `@result`；
2. **副作用占位符** —— 地址模板里嵌 `{{cookie.removeCookie(...)}}`，调用有副作用但返回值不该进地址；
3. **jsLib 的 JSON 映射形态** —— `"jsLib": "{\"包\":\"https://…/jsLib.js\"}"`，要按值下载再求值；
4. **带参数尾巴的相对地址** —— 章节地址 `…/programs/19167943,{ "webView": "true" }` 补全时把尾巴拼坏；
5. **中文进了请求头** —— 外站脚本源（qyyuapi 等）路径含中文，整批在发请求前失败。

目标：这五类一次修掉，补测试，用 live 抽样确认原先被挡住的源能走到站点侧。

## 核验发现

**上游语义（`AnalyzeUrl.initUrl`）**：`analyzeJs()` → `replaceKeyPageJs()` → `analyzeUrl()`。
`JS_PATTERN = <js>([\\w\\W]*?)</js>|@js:([\\w\\W]*)`，逐块求值，`result` 在块间传递，
尾部文本替换 `@result`；`{{...}}` 在 JS 之后再展开。原生实现只做了 `{{key}}/{{page}}`，
所以整段/尾部脚本从来没跑过 —— `java.put` 上游返回 `String`（`AnalyzeRule.kt`），
副作用调用的返回值会被当成文本拼进地址。

**中文请求头会让整批脚本源失败。** JDK `HttpRequest` 对 header 值只收可打印 ASCII，
遇到中文直接抛 `IllegalArgumentException: invalid header value: "https://qyyuapi.com/sy/js/再漫画/jsLib.js"`
（用最小 Java 探针复现）。Reload 拼 Referer 时把脚本地址原样塞进去，于是 10 份 JSON-jsLib
源与多份 url_js 源全卡在同一条报错上。

**`lastError` 跨线程串源。** 「🎃精华书阁🎃」正文规则是纯 CSS（`id.nr@html`），却报
「脚本里的 JSON.parse 解析失败」。原因是 `JsSandbox.lastError` 是单个 `@Volatile` 字段，
并发抽样时别的书源的脚本错误留在了这里，被当成本次失败原因。线程池复用线程后必然发生。

**空响应被 JSONPath 顶罪。** 「听姬」搜索直接 curl 站点返回 HTTP 200 且 0 字节，
引擎把空串交给 JSONPath，用户看到的是 `json string can not be null or empty`。

**登录脚本不该在普通规则里预跑。** 修完请求头后 live 抽样里仍有 5 份 qyyuapi 系源报
`ReferenceError: “put” 未定义 (loginScript.js#1(eval)#10)`。把远端 `loginUrl.js` 拉下来看，
第 10 行是裸 `put($$$)`，给整个脚本生态落默认设置；这类脚本**只在登录流程里**才有意义。
上游 `BaseSource.login()` 与登录界面才会执行 loginUrl JS，普通搜索只加载 jsLib。
我们此前每次求值都预跑 loginScript，等于把登录期副作用塞进搜索路径。改法是：
`JsExecutionContext.includeLoginScript` 默认 false，只有登录入口解析、登录 UI/动作 v1/v2
才置 true；同时在沙箱补上全局 `put`（整份写回书源变量）、暴露 `source.loginUrl`、
把 `source.putVariable` 对齐到同一个存储。

**登录入口解析本身要走登录流程。** `loginBrowserStartUrl` 以 `login(true,false)` 取脚本要打开的地址，
如果不同时执行 loginUrl JS，`login()` 根本不存在（两条既有测试因此变红）。
这里单独置 `includeLoginScript = true`；`loginCheckJs`、字段脚本、正文脚本仍保持默认。

## 决策与取舍

- **地址脚本**：`applyUrlScripts()` 复刻上游三步顺序，`renderUrl(expandScripts=true)` 在
  展开模板后执行脚本；`@js:` 后无内容（纯 `@js:` 前缀）按空脚本处理，不误吞后续文本。
- **副作用占位符**：`{{...}}` 里以 `cookie.`/`java.put` 等已知副作用前缀开头的调用整体替换为空串；
  其余表达式照常取值。宁可漏判（值原样展开）也不误删正常取值。
- **jsLib JSON 映射**：解析成 `名称 → URL` 后逐个走 `reloadFetchUrl`（挂浏览器 UA/Referer）
  下载，正文进内存缓存（上限 64 条，按整表清空淘汰）；library 与 loginScript 分开求值，
  避免登录脚本里的 `return` 把库函数截断。
- **带尾巴的相对地址**：`absolute()` 先按 `,{` 拆出 options 尾巴，URL 解析失败再退回
  `java.net.URL`；拼接只作用于纯地址部分，尾巴原样回贴。
- **请求头编码**：新增 `headerSafe()`，只对非 ASCII 与控制字符按 UTF-8 百分号编码，
  `reloadFetchUrl` 的 Referer 与 `buildRequest` 的每个头值都过一遍；纯 ASCII 原样保留。
- **失败归属**：`lastError` 改 `ThreadLocal`，`withSourceContext` 入口清空；
  空响应在 `bookItems` 里先判掉，直接说「上游响应为空（0 字节）」。

## 验证

- 新增 `RuleUrlScriptsTest`（7 条）与 `SandboxErrorScopeTest`（2 条）；`Reload` 的 Referer
  断言改为 header-safe 形态（编码后仍指回脚本地址，纯 ASCII 不变）。
  新增一条端到端判据「远端搜索脚本自取登录地址时裸 put 把默认变量写回」：
  `eval(String(source.loginUrl))` 里的裸 `put` 必须落到 source.variable，搜索地址用它拼出来。
- 后端全量：896 条测试，0 失败（首轮唯一红是上述旧断言，更新后复跑通过；
  登录入口两条既有测试确认 `loginBrowserStartUrl` 必须走登录流程后转绿）。
- live 抽样（36 份受影响源）：修复前 1 份取到内容、1 份被串源错误误报；修复后 JSON-jsLib
  源不再报 `invalid header value`，剩余失败均为站点侧（403/523、需登录、0 字节）。
