# 退役的门禁

这里放**被测对象已被删除**的门禁。文件保留是为了留下"当初为什么这么判"的记录
（与 `docs/` 归档同一条纪律：历史叙述可以留，但不能继续冒充活的判据）。

CI 的 `tools/verify/*-check.mjs` 通配符扫不到子目录，所以放这里就等于停用 ——
不需要改 workflow，也不会有人以为它们还在跑。

## 清单

### `next-mount-check.mjs` / `next-ui-check.mjs`（2026-10-21 退役）

测的是 0.6.0 那套「新骨架挂到同端口 `/next/`」的架构：

- `/next/` 返回 200 与 HTML、资源地址带 `/next/` 前缀、index 是 no-cache
- 浏览器停在 `/next` 上加载新骨架自己的 bundle
- `.grid-cards`（书架网格）/ `.md-list`（书源主从）/ `.list-group`（设置成组）
  这些 UI 原型的形状

那套架构后来被**整个替换**：SPA 直接挂根路径（`/` 返回带 `<script type="module">` 的壳），
`.grid-cards` / `.md-list` / `.list-group` / `.shell-nav` 这些 class 在当前前端
**一个都不存在**，`/next/` 返回 404。

所以这两个门禁从某个版本起就**必然红**——不是产品坏了，是它们盯着一个不存在的东西。
留着它们在 CI 里一直红，比没有门禁更糟：会训练所有人忽略 CI 的红。

## 复活的正确做法

不要把这些文件搬回去改。如果将来又要做"同端口挂第二套前端"，
按**当时**的架构重写判据（参考 `ui-shell-check.mjs` 的写法：现量、真浏览器、判行为不判 class 名）。
