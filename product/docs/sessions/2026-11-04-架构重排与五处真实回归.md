# 架构重排（后端分层 / 前端 features / API 按域）与随之暴露的五处真实回归

## 背景与目标

0.2.14 的三条并行重构：

1. **后端**：`Database.kt`（641 行）、`Routes.kt`（182 行）两个"什么都装"的文件收口成组合根；
   规则引擎抽出 `RuleProcessor` 扩展点契约；系统域端点独立成 `http/system/` 子包。
2. **前端**：业务域从 `src/{reader,bookshelf,sources,settings}/` 迁到 `src/features/`；
   新增 Slot / Extension 插件外壳（`plugins/`）；`lib/api.ts`（1085 行）按域拆成 `lib/api/domains/*`。
3. **契约**：`agent-api.json` 与 `http/` 路由文件的双向核对判据要能看见新的子包目录。

目标不是"文件变小"，而是**每个变化都有判据盯着**。这次重排真正有价值的产出，
是它把四处此前没人注意的真实缺陷顶到了水面上（见「核验发现」）。

## 核验发现

动手前先量，四条与预期不符：

| 现象 | 真实原因 | 性质 |
|---|---|---|
| `tsc --noEmit` 报 **451** 个错误 | ① `lib/api.ts` 里 `from './api'` 被解析成**自身**（文件优先于同名目录），域对象全部退化成 `any`；② 文件迁入 `features/` 后相对路径少一层 | 重构事故 |
| 后端 18 个 HTTP 集成测试全红，报 `no such column: last_read_at` | `Schema.kt` 把 `book_shelf_last_read_idx`（挂在 `book_shelf.last_read_at` 上）**重复建到了 `reading_progress` 上** —— 那张表没有这一列 | 重构事故 |
| `api.cover(key)` 返回值变了 | 拆域时把 `cover(key) → /api/covers/<key>` 与 `coverProxy(url)` 合并成一个函数，后者对非 http(s) 原样返回 | **真实回归** |
| `SourceLoginTest` 403 | 我按"仅服务自身同源"收紧了 Cookie 同步闸门，把原设计的「**该书源自己的域**发来的跨站同步」也拒了 | **过度收紧** |
| `ModelListTest` 抛 `UnreachableTargetException`（回环） | `ProviderHttp` 改用受控 client 后，闸门在**发包层无条件拒回环**，把 provider 层已经放行的 `LEGADO_AI_ALLOW_LOOPBACK_BASEURL` 口子又关了回去 —— 本机 Ollama / LM Studio 直接不可用 | **过度收紧** |

另外两条此前就存在的问题：

- `ApiCatalog.test.ts` 只 `readdirSync` 顶层，`http/system/` 里的 9 条系统端点被判成"代码中不存在"。
  合成锚点缩进写死 4 空格，与抽成 `fun Route.xxxRoutes()` 后的端点缩进同级，`while (indent >= 本行) pop`
  把 `/api` 前缀整段弹掉。
- 章节过滤/虚拟滚动的性能判据用**单次取样 + 平均值**，并行门禁下比值随机跨过 12× 上限；
  且"大结局"对照组在 20k 数据集里一条都不命中（与 5k 命中 1 条不对称），量出来的不是复杂度而是数据集差异。

## 决策与取舍

- **`lib/api.ts` 保留为兼容层**，不做"一刀切改调用点"。它 `export * from './api/types'` 透出全部类型，
  并用 `from './api/index'`（显式目录入口）避开自引用。理由：一次改 100+ 调用点的风险远高于收益，
  且兼容层能让新旧写法并存，随时可以逐页迁。
- **插件依赖零引入**：`attachmentStore` 原本用 zustand，但仓库没有这个依赖。
  改成 React 内置 `useSyncExternalStore`，对外形状不变（`useAttachmentStore()` 返回
  `{attachments, attach, detach, ...}`）。宁可少一个依赖，也不给打包链加一个"要装才有"的洞。
- **`RuleProcessor` 只交付契约，明确标注"尚未接入 RuleRunner"**。
  `RuleRunner` 2413 行，Jsoup / Rhino / JS 上下文混在同一条链路里，改成"声明式处理器 + 调度器"
  是一次必须带等价性测试的独立重构。把注释写成"已经接入"比没做更糟 —— 后来人会照着假前提动手。
- **ReaderScreen 只拆出 TTS 一块**（`ReaderTtsContext` + `ReaderTtsManager`，约 290 行，含悬浮条、
  设置弹层、离线确认框）。剩余 2600 行的目录/正文/分页/设置拆分牵动十几个跨域状态
  （快捷键、Ctrl+F 聚焦、跨章续播都要读），需要独立一轮带交互回归的改造，不在本轮硬塞。
- **性能判据两档交替取样**（同一个循环里 small / big 轮着测，各自把窗口拉到 ≥10ms 再折算单次），
  **不放宽 12× 上限**；对照组数据集改成与实验组**同命中率**。
  实测：「第2500章」从被判 12.0×（单次取样把 big 段被抢占记成复杂度回归）回落到 **4.58×**，
  与线性期望 4× 相符 —— 判据强度不变，噪声不再伪装成回归。
- **Cookie 同步闸门按 HEAD 恢复**：`allowCookieSyncOrigin(call, database, sourceJson)` 恢复
  `WebViewProxy.allowedDomains` 域名匹配，只保留同源单独放行那一条支路。
- **回环口子跟着连接走，不跟着 client 单例走**：`NetworkSecurity.newHttpClient` 增加 `allowLoopback`，
  `GuardedHttpClient` 在放开时只跳过回环（私网 / 链路本地 / CGNAT / 保留段照旧拒）。
  `ProviderHttp` 因此持有两个 lazy client（严格 / 放开回环），在 `sendWithRetry` 里按
  `loopbackAllowed` 选一个 —— 若给同一个单例传参，「某个连接放开了」会悄悄扩大成「所有出站都放开」。

- `web/test/ApiCatalog.test.ts` —— 157 条端点双向覆盖（含子包目录），"代码里没有的端点"与"目录里漏的端点"都红。

- `web/test/UiContract.test.ts` —— 浮层 Esc/外壳/role/名字、类名必须能在样式表命中。
