# AI 外部工具接入（MCP 客户端）落地（0.2.33 / build 46）

## 背景

`docs/STATUS.md` 的「已知缺口」里最后一项 AI 能力是 MCP：只有 55 个内置工具，接不了外部服务。
`docs/研究-借鉴-refgd与MD3.md` 把它列为 P0，并写清了参照实现的形状（JSON-RPC over HTTP、
`Mcp-Session-Id`、`nextCursor` 翻页、工具挂 `mcp` 组）。`ToolMeta.origin` 当初就是为外部工具留的字段，
一直是 `null`（内置）或 `plugin:`（插件已移除）。

这一轮只做这一件：**能接上外部 MCP 服务，把它的工具变成 AI 的能力**，其余缺口不动。

## 做了什么

| 文件 | 职责 |
|---|---|
| `ai/McpServerStore.kt` | `{home}/agent-mcp.json` 的读写；id/地址校验；`deriveId` 由名字派生 id |
| `ai/McpClient.kt` | JSON-RPC 2.0 over HTTP：握手 / 会话 / 翻页 / 调工具 |
| `ai/McpBridge.kt` | 把远端工具挂进 `ToolRegistry`，同步状态、摘干净、60s 缓存 |
| `ai/Agent.kt` | `val mcp by lazy { McpBridge(registry, homeDirectory) }`（构造时**不外呼**） |
| `ai/AgentConnection.kt` | `val mcp` 暴露给路由层 |
| `Application.kt` | `ApplicationStarted` 里 `agentConnection.mcp.sync()`（端口已 listen 之后，不挡启动） |
| `http/AgentApiRoutes.kt` | 四条端点：`GET/POST /api/agent/mcp`、`POST /api/agent/mcp/refresh`、`DELETE /api/agent/mcp/{id}` |

### 协议细节（三条都是踩过才知道的）

1. **响应可能是 JSON，也可能是 SSE。** streamable HTTP 的服务端可以回 `text/event-stream`，
   里面若干 `data: {...}`，中间还夹着 `notifications/progress`。只认 JSON 的客户端会看到"空 body"。
   所以 `extractJsonRpc` 两种都解，SSE 取**最后一条带 result/error** 的。
2. **`Mcp-Session-Id` 由服务端在 `initialize` 的响应头里给**，之后每个请求带回去；
   会话过期时服务端回 404，客户端必须**重新握手一次再重试**（只重试一次，一直 404 说明是别的问题）。
3. **`tools/list` 有 `nextCursor` 翻页**，最多翻 20 页（坏游标不许把进程拖死）。

`tools/call` 的 `content` 数组拼成一段文本：`text` 直取，`image` / `resource` 给一句占位
—— 静默丢掉内容比给占位更糟，模型会以为自己看到了全部。

### 三条刻意的边界

- **挂不上不算错**：服务没开、地址写错、协议不兼容，都只让那一组工具为空 + 一条状态原因，
  聊天照常。一台外部服务没起来不该让整条对话不能说话。
- **工具一律进 `mcp` 组，默认不下发**：`ToolSelection` 的默认组里没有它；模型仍能用
  `tool.search` / `tool.call`（`program` 组，始终可用）够到。想让它直接看见，用户去「AI 工具」打开那一组。
- **摘干净**：停用 / 删除 / 改名时，服务注册过的工具一起摘掉。留一个"调用必然失败"的工具
  比没有更糟 —— 模型会一直试。

### 出站闸门

复用 `NetworkSecurity`：**放行回环**（MCP 服务天然在本机，Docker 发布的端口也在回环上），
私网 / 链路本地 / CGNAT / 保留段照旧拒绝 —— 与 AI 连接同一条口径，不因为多了一份配置文件就多开一道门。
另外硬拒"指向这台服务自己"（`ProviderHttp.refusePointingAtSelf`）：那等于绕过唯一的写保护。

## 活体实测（本机 0.2.33 / build 46）

真起一个假 MCP 服务（`product/tmp/fake-mcp.mjs`，不入库）+ 真服务：

```
POST /api/agent/mcp  {"name":"本地文件","url":"http://127.0.0.1:3399/mcp"}
→ {"id":"srv-303a1ed3","ok":true,"toolCount":2,...}

GET /api/agent/manifest
→ 59 个工具，mcp 组 2 个：mcp.srv-303a1ed3.echo（params text*）、mcp.srv-303a1ed3.now
  origin 都是 mcp:srv-303a1ed3

DELETE /api/agent/mcp/srv-303a1ed3
→ {"deleted":"srv-303a1ed3"}，清单回到 57 个，mcp 组 0 个
```

### 活体测试与自审逮到的三个真 bug（都已修）

1. **中文名当 id 会被拒**。`normalize` 要求 id 匹配 `[a-z0-9][a-z0-9_-]{0,31}`，
   而"没给 id 就用名字"意味着用户填「本地文件」时收到一句"id 只能用小写字母…"——
   名字是给人看的，id 是实现细节。改成 `deriveId`：能取字母数字就取（`本地 File` → `file`），
   一个都没有就用名字哈希（`srv-303a1ed3`），稳定且不同名不撞。
2. **`ok:true` 的卡片上挂着"尚未同步"**。`mcpViews` 里 `status?.error ?: if (server.enabled) "尚未同步"`，
   连通时 `error` 为 null 就落到了兜底文案。改成"有状态用状态里的原因，没有状态才说尚未同步"。

这两条静态判据都看不见，只有真发一次请求才露出来。

3. **点「停用」会抹掉已配的 Authorization。** 界面只回传请求头的**名字**不回传值
   （那里面是 token），所以"停用/启用"这类请求必然不带 `headers`；而后端原来按
   `req.headers.orEmpty()` 覆盖，于是一次启停就把鉴权头清空了。改成"不传 = 沿用原值"
   （与连接档案里 `apiKey` 同一条口径），并在 `AgentRoutesHttpTest` 里加了一条端到端判据。

## 没做的（有意）

- **stdio 传输**：MCP 本地服务常用 stdio，但桌面壳里拉起子进程要另一套生命周期管理；
  先做 HTTP，够了再说。
- **resources / prompts / sampling**：界面里没有落点，做了也只是清单里多几行没人用的能力。
- **私网段放行**：与 AI 连接同一条口径。真要接局域网里的服务，得先想清楚怎么不把内网扫一遍。
- **工具调用的嵌套 schema**：`inputSchema` 只取顶层 properties 映射成我们的扁平 `ToolParam`。
  嵌套对象/数组在模型侧会退化成"宽松对象"，这是当前 `ToolParam` 形状的限制，不是 MCP 的。
