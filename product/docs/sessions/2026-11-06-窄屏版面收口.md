# 窄屏版面收口（0.2.20 / build 21）

## 背景

390×844 实机截屏审查（Chrome，`isMobile` + `deviceScaleFactor: 2`，逐页全页截图 + 机器判据）。
五处"看起来像坏了"的版面事实，都是**被裁掉半个字 / 被压成竖排 / 被别的东西盖住**这一类，
不是审美偏好：

| # | 现象 | 量到的数 |
|---|---|---|
| 1 | 顶栏最后一个入口只露出半个字 | 6 个入口共 252px，可用 234px |
| 2 | 书架卡片的三项副标题被压成竖排 | 徽章 37×39、章节 34×32（两个字上下叠） |
| 3 | 发现卡片每张下面挂一行孤零零的「•」 | 源站 `lastChapter` 返回的就是 `•` |
| 4 | 「新建分组」压住最后一颗分组 chip 的计数 | 滑轨 clientW 354 / scrollW 539，按钮 294–372 盖在「本地 0」321–386 上 |
| 5 | 首启协议最后一行被硬切一半 | 正文可视 471px / 内容 715px，padding-bottom 0 |

## 做了什么

1. **顶栏**（`app/AppHeader.tsx`）：选中项变化时 `scrollIntoView({ inline: 'center' })`；
   按 `scrollWidth - clientWidth > 1` 加 `is-overflowing`，只在真溢出时挂右侧渐隐。
   窄屏内边距 8px → 6px（6 个入口 252 → 228px，放得下）。
2. **书架卡片**（`styles.css`）：`.shelf-card-meta` 允许换行，子项 `white-space: nowrap` ——
   宁可换行，不许竖排。
3. **发现卡片**（`features/explore/ExplorePage.tsx`）：新增 `exploreMeta()`，
   纯标点/占位串（`•` `·` `...`）一律当没有，三样都没有就整行不渲染。
4. **分组条**（`features/bookshelf/ShelfPage.tsx` + `styles.css`）：拆两层 ——
   `.shelf-group-scroll` 负责横滑，「新建/删除分组」是它外面的普通 flex 子项。
   原来那颗按钮靠 `position: sticky; right: 0` 钉在右端，正好盖住分组计数。
5. **首启协议**（`components/FirstRunAgreement.tsx`）：按"还剩多少没读"
   （`scrollHeight - scrollTop - clientHeight > 2`）加 `is-more`，底边 26px 渐隐；滚到底摘掉，
   否则最后一行会被渐隐糊掉。

## 判据

`web/test/NarrowScreenPolish.test.ts`（5 条，全静态、秒级）：`exploreMeta` 的占位符过滤是真单测，
其余四条盯结构事实 —— 有没有 `scrollIntoView`、溢出类按什么判、`.shelf-group-scroll` 是不是
在按钮之前闭合、`is-more` 的 mask 规则在不在。**不锁具体文案**。

## 验证

- `npm --prefix product/web test` → 916 项全绿（原 911 + 新增 5）
- `node product/scripts/version-check.mjs` → 7 处版本一致，都是 0.2.20
- `node product/tools/verify/bundled-ui-check.mjs` → 5 项全过（含"运行中的实例真能发出 bundle"）
- 390px 复测：分组计数不再被盖；协议底部由"切半行"变为渐隐；320px 顶栏溢出时渐隐出现、
  当前项完整可见

## 没做的

- 分组 chip 在 390px 仍只能放下约 3.5 颗（413px 的内容塞进 268px 的滑轨），横滑是必需的；
  被裁的那颗药丸本身就是"还能往右滑"的提示，没有再叠一层渐隐。
- 订阅页的删除键仍是 30×30 无边框图标键（`.icon-btn` 全站约定），没有为了对齐另外两颗
  按钮单独改它。
