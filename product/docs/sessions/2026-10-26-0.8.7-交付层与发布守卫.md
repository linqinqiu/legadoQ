# 0.8.7：交付层压缩缓存 + 发布守卫 + 浮层避让

## 背景与目标

0.8.6 收口后做了一轮全量评审，结论是"功能不缺，交付链在漏"。这一轮把评审里**可验证、可回退**的那部分真正落地：
静态资源的传输与缓存、"跑的是不是当前构建"的自证、以及三处量出来的界面遮挡。安全两项（Cookie 域、
AI 删除工具的 `confirm`）刻意没混进来 —— 它们改的是行为语义，要单独一轮。

## 核验发现

动手前量的数，与评审时的两处判断不符，都记下来：

| 项 | 评审时的说法 | 实测 |
| --- | --- | --- |
| fatJar 为何没更新 | 运行中的 JVM 锁住 `-all.jar`，Windows 覆盖不了 | **错**。服务运行时 `:app:fatJar --rerun-tasks` 覆盖成功。真因是 `fatJar` 没挂进 `assemble`/`build`，只被 `npm run build` 调用 |
| 阅读器每 3 秒拉书架 | 阅读期常驻开销 | **错**。`ReaderScreen.tsx:483-489` 带 `state !== 'caching'` 守卫；静置 16 秒 `/api/` 增量为 0 |
| 书源列表 5,598 条全渲染 | 无虚拟化会卡 | **错**。界面是"已显示 120 / 5598，点击加载更多"，客户端分页 |
| AI 球压住"2 字"按钮 | 桌面与手机都压 | 只对一半：桌面已是 1120×1030 居中模态，与球**不相交**；手机 sheet（390×658）与球重叠 2,116 px² |
| 后端是不是瓶颈 | 不确定 | 不是。`/api/sources` 1.06 MB / 79 ms，其余 11–39 ms；WAL + 16 读连接 + 13 处索引到位 |
| `/assets` 交付 | 未压未缓存 | GET 只回 `Content-Length` + `Content-Type`；HEAD 直接 404（`staticResources` 不接 HEAD） |

还量到两个仓库外的隐患：这台机器上有个不在仓库里的拉起方式（相对路径 `-jar`）会在构建中途把服务拉回来，
17:57 那次它打开的是**写了一半的 jar**，于是 `/` 报新 bundle、`/healthz` 报旧 bundle，两边互相矛盾；
`.github/workflows/` 下 7 个 yml 全部塌成一行（0 换行 + BOM），GitHub 根本解析不了，CI 自仓库重组起从未真的跑过。

## 决策与取舍

- **手写 gzip 而不是装 `ktor-server-compression`。** 插件是给所有响应套一层，会连 SSE、TTS 音频流、
  备份下载一起压；而体积大头只有烤进 jar 的静态文本。于是 `/assets` 换成显式路由，字节与压缩结果常驻内存
  （整批约 1.2 MB），带 ETag / `If-None-Match` / HEAD。代价是只覆盖静态表面 —— 将来要压 `/api/*` 的 JSON
  再走插件，并且必须排除流式。
- **`index.html` / `sw.js` / `manifest` 继续 `no-store`。** 它们的名字不带哈希，缓存住就等于"改了看不到"；
  与 `registerType: 'autoUpdate'` 是一套。新增判据专门钉住这条，防止以后有人"顺手给静态都加缓存"。
- **守卫放在构建与启动两侧，而不是只在 CI。** 个人项目最常见的动作是本地改完直接重启，CI 拦不住它。
  `start.mjs` 启动前比 mtime、启动后比指纹；`npm run build` 第三步跑 `tools/verify/bundled-ui-check.mjs`
  比对 jar / processResources / dist / 运行中四方。
- **挑包与指纹收进 `scripts/runtime.mjs`。** 原先 `start.mjs`、`tools/make-cds.mjs`、新门禁各写一遍
  `sort().pop()` —— 三处必须挑同一个包，否则门禁绿而跑的是另一个；顺带修掉字典序在 `0.8.10` 会挑回
  `0.8.6` 的潜伏 bug。
- **遮挡用 CSS `:has()` 而不是把"有没有浮层"提到 React 状态。** 纯表达"有浮层时球不该在"，不需要每个
  弹层都记得传 props；`.ai-fab-open` 排除在外，否则球自己展开的助手面板收不回去。
- **窄屏球位改在原有那条媒体查询里。** 原先它写 `bottom: 14px`、注释说"避免挡住底部操作条"却没量过
  （导航实测 77px 高）。改在原地并留一句"位置只有一处来源"，判据钉住"窄屏 `.ai-fab` 规则只许一条"。

## 落点与判据

| 改动 | 位置 | 谁盯着它 |
| --- | --- | --- |
| `/assets` immutable + gzip + ETag + HEAD | `StaticWeb.kt`（`BundledAssets`） | `StaticAssetsHttpTest.kt`（5 例，含 304、解压后字节一致、穿越拒绝、`index.html` 仍 no-store） |
| `/healthz` 回显 `ui` / `startedAtMs` | `BuildInfo.kt`、`Models.kt`、`Application.kt` | 同上（断言 `ui` 等于 dist 那个哈希） |
| `assemble` 依赖 `fatJar` | `app/build.gradle` | 构建产物一致性：`bundled-ui-check.mjs` |
| 启动前拒旧包、启动后比指纹 | `start.mjs` | 手工 + `bundled-ui-check`（反向验证过：假服务发旧 bundle 时确实 FAIL 且退出码 1） |
| 挑包与指纹共用一份 | `scripts/runtime.mjs` | `start.mjs` / `make-cds.mjs` / 门禁三处引用 |
| 搜索切片订阅 | `lib/searchStore.ts`、`main.tsx` | `SearchSlice.test.ts`（含行为断言：无关写入换整份快照、不换切片） |
| `splitBody` 内容级缓存 | `reader/ReaderScreen.tsx` | 现有分页判据不回归 |
| 球避让浮层、抬离导航、窄屏文案 | `styles.css`、`sources/SourceEditorPanel.tsx` | `FloatingLayerOverlap.test.ts`（3 例，媒体查询按花括号配平取块） |

实测：首屏 JS+CSS 由 919,289 B 降到 252,872 B（−72.5%）；窄屏球底边由 830 抬到 768（导航顶边 767）；
弹层打开时球 `opacity=0` 且 `pointer-events:none`；7 个页面 0 报错。
门禁：后端 618 项、前端 740 项全绿，`verifyFramework` / `depth-check` / `version:check` /
`changelog:check` / `docs:api-check` / `bundled-ui-check` 全绿；`ui-shell-check` 60/61，
唯一 FAIL 与改动前同名同细节（主题叠加的反向对照），单列待查。

## 未做与后续

- 安全两项：`/api/sources/{id}/login-cookie` 仍接受调用方给的任意 `url`、Origin 判据仍有子串回退、
  AI 六个删除工具仍不过 `confirm`。需要产品判断，单独一轮。
- `fatJar` 应改成"写临时名 + 原子替换"，否则构建中途被拉起仍会读到半包。
- 路由级拆包（入口 700 KB / 预缓存 1,344 KiB）、`api.ts` 超时与错误分类、`Dialog` 焦点陷阱。
- gzip 生效后 AI 流式与 TTS 音频的真机回归。
- `.github/workflows/` 7 个文件需要整体重建（当前不可解析），顺带把路径改到重组后的 `product/`。
