# 文本解码策略统一：文件与远程内容也能读 GBK

## 背景与目标

0.2.2 只把**请求体**改成严格解码，其它吃文本的入口仍是"解不出来就当 UTF-8"。
本批把这些入口全部收口到同一套策略：请求体保持严格（编码不对就 400），
文件与远程内容做自动识别（先 BOM，再严格 UTF-8，再声明的字符集，最后 GB18030）。

## 根因

`String(bytes, UTF_8)` 与 `readText()` 在 JDK 里用的是 `CodingErrorAction.REPLACE`，
**从不抛异常**——无法解码的字节变 U+FFFD，所谓"失败再换 GB18030"的回退永远走不到。
仓库里几处 `runCatching { String(bytes, UTF_8) }` 的兜底因此是死代码：
GBK 备份包、GBK 订阅源、GBK 的 EPUB 章节都会被整段替换字符化。

## 修改

新增 `io.legado.TextDecoding`，两个入口：

- `decodeStrict(bytes, charset)`：`CharsetDecoder` 开启 `REPORT`，失败抛
  `CharacterCodingException`。请求体用。
- `decodeTextAuto(data, declared)`：BOM（UTF-8/UTF-16BE/UTF-16LE）优先；宽字符声明
  （UTF-16/UTF-32）先试；然后严格 UTF-8；再试声明字符集；再试严格 GB18030；
  最后才用替换模式。文件与远程内容用。
- `charsetOf(contentType)`：手写 `;` 分割取 `charset`，避免依赖 MIME 解析器对畸形头的宽容度。

顺序的理由：整份字节能通过严格 UTF-8 校验，几乎可以断定就是 UTF-8（中文 GBK 文本
极少恰好构成合法 UTF-8 序列）；服务端把 GBK 内容标成 UTF-8 很常见，所以先试 UTF-8
再信声明；GB18030 是 GBK/GB2312 的超集，兜住老中文文本。

接入点：

- `backup/BackupImporter`：zip 条目与整包 JSON 都走 `decodeTextAuto`。
- `localbook/LocalBookParser`：EPUB 的 container.xml、OPF、NCX、nav 与章节 XHTML；
  原来那份 40 行手写启发式删除，统一调用 `decodeTextAuto`。
- `subscription/SubscriptionService`：按响应 `Content-Type` 的 charset 提示解码。
- `http/ReplaceRulesRoutes`：`/import` 请求体改 `receiveStrictText()`；`{url}` 远程抓取
  按响应头 charset + 自动识别解码。
- `http/SourcesRoutes`：外部登录 POST 的小 JSON 体改严格解码，且放在 `runCatching`
  之外——编码错要回 400，不能被"解析失败就当没传"吞掉。
- `http/MediaRoutes`：HLS 播放列表与 HTML 嗅探页面按 `media.contentType` 解码。
- 前端 `lib/importFromUrl.ts` 新增 `decodeImportText`（BOM → 严格 UTF-8 → 严格 GB18030），
  地址导入与本地文件导入共用；`SourcesPage` 的 `file.text()` 换成按字节解码。

请求体读取抽成 `http/StrictRequestText.kt`（`receiveStrictText()` + 统一错误文案），
`StrictJsonConverter` 改为复用它，两处不再各写一份解码逻辑。

## 明确不改的

- `WebViewProxy` 的 data URL：由页面自己生成，编码可控。
- `JsSandbox.base64Decode`：语义要对齐上游 legado 的返回类型，不做字符集猜测。
- AI 提供商的错误响应体：只用于拼错误消息，不进用户数据。
- `UpdateCheck`：GitHub API 固定 UTF-8。

## 验证

- `TextDecodingTest` 9 条：严格解码对 GBK 字节抛错、GB18030 自动识别、
  UTF-8 优先于撒谎的 GBK 声明、BOM 剥离、UTF-16 声明、`charsetOf` 解析。
- `BackupImportTest` 新增 GB18030 备份包用例：书源名与替换规则中文原样保留。
- `StrictJsonRequestTest` 新增：净化规则导入 GBK 字节 → 400 且库不变；
  `charset=gbk` → 200 且值正确。
- `LocalBookParserTest` 新增：GBK 编码的 XHTML 章节能解析出正文。
- 前端 `ImportFromUrl.test.ts` 7 条：UTF-8、GBK、BOM、UTF-16LE、非法字节退化、空输入、URL 归一化。
