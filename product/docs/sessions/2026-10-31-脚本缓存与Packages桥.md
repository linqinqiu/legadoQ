# 脚本缓存、Packages 白名单与剩余 java 桥（0.2.9）

## 背景与目标

0.2.6 把「库里有源引用、而桥上完全没有」的方法补掉一批，剩下的缺口按 256 份候选源
（用到了当时未实现的桥方法）复跑还剩 15 份脚本报错。逐条看报错，挡路的是四类：

1. `Packages.*` 与 `JavaImporter` —— 加解密、Base64、HashMap/ArrayList、okhttp3 都从这里进；
2. `java.ajaxAll` —— 番茄系、书山、云端聚合、蓝批、期刊、顶级看书用它一次抓多章；
3. 全局 `cache`（上游 `CacheManager`）—— 49 份源在写、36 份在读，沙箱里原来直接 ReferenceError；
4. 零散小工具：`getUserAgent`、`htmlFormat`、`toURL`、`importScript`、`cacheFile`。

另外登录信息只支持属性访问（`m.token`），社区源普遍写 `m.get("token")`；HashMap 同理。
这一版把这四类一次补齐，并把 live 抽样里的脚本报错从 11 份压到 2 份。

## 核验发现

**Rhino 1.8 的稠密数组不能用字符串下标读。** 元素全是数字的 JS 数组走稠密存储，
`ScriptableObject.getProperty(array, "0")` 返回 `NOT_FOUND`；当成 0 处理后，
`[65,66,67]` 经 `java.bytesToStr(java.base64DecodeToByteArray(...))` 解出三个 NUL。
这条不是一处：`bytesOf`、`TextUtils.join`、`System.arraycopy`、`ajaxAll` 入参、
`ScriptCrypto.toBytes`、ArrayList 贴片全踩。现在统一走 `elementOf(value, int)`：
先 `getProperty(value, index)`（int 下标 → `Scriptable.get(int, …)`），拿不到再用字符串下标兜底。

**`NativeString` 在 Rhino 1.8.0 是包私有类**，Kotlin 无法引用。响应对象是
`cx.newObject(top, "String", …)` 造出来的，转换字节时只能按 `className == "String"`
把它当文本，否则会按数组读成长度 0。

**裸 Kotlin 异常穿透 JS `try/catch`。** `importScript` 取不到内容时抛 `IllegalStateException`，
脚本侧接不住，最后变成「cannot be cast to java.lang.Error」的解释器崩溃；
`org.mozilla.javascript.EvaluatorException` 则能被 JS 捕获（实测）。

**live 复跑（`tmp/triage_gap_029.py`，48 份抽样：Packages 18 / ajaxAll 10 / t2s 8 /
webView 6 / misc 6）**：脚本报错 11 → 2。剩下两份都不是本轮方法的问题 ——
「长佩文学」正文要 `baseUrl` 带 `nid=`/`chapter_ids=`（调试入口给的章节地址形态不同，
`match` 返回 null 后取 `[0]`），「城堡小说」用的是仍未实现的 `java.webView`。
站点侧失败 46/48，多为超时、403/404/523、证书与拦截页，与桥无关。

## 决策与取舍

**不给真 Java 对象，只给贴片。** `ClassShutter` 依旧是 `{ false }`；`Packages` 能解析的
只是 `CLASS_NAMES` 里列出的 43 个类，`PackageNode.get` 对其它名字返回 `NOT_FOUND`，
`java.lang.Class`/`Runtime` 与 `System.getClass` 都拿不到。`org.jsoup.*` 走既有的
白名单 Jsoup 包装，不另开入口。okhttp3 只做同步 `newCall().execute()`，请求统一走
`RuleRunner.fetchResponse`（SSRF 闸门、Cookie、字符集都在那条路上）。

**`JavaImporter` 按「精确类名优先、再按包前缀」解析**，`with(importer){…}` 只暴露导入范围内的名字；
`importPackage` 跳过 JS 内建名（`String`/`Array` 等），避免把 JS 原生构造器顶掉。

**`cache` 键按书源隔离。** 上游是单机全局键空间，但多源并发跑在同一个 JVM 里，
同名键（`imgstyle`）会真的串数据。内存层是 2048 条的 LRU，读也刷新顺序；
落盘在 `script_cache(source_id, key, value, deadline, updated_at)`。

**内存层也认 deadline。** 上游内存值不看过期时间，进程活着就一直返回旧值；
常驻服务里「缓存 5 分钟」会变成永久，所以内存层同样按 deadline 判，过期即删。
`saveTime <= 0` 表示不过期；对象值 JSON 序列化后落库（上游是 `toString()`，`[object Object]` 不可用）。

**`ajaxAll` 用 8 线程守护池、按入参顺序取 Future。** 单条失败用响应对象承载失败文案，
不拖累其它条；空入参回空数组。响应对象的构造放在调用线程，不把 Rhino 作用域带进池里。

**`importScript` 对 http(s) 地址不补全、其余按书源地址解析**，同一地址只抓一次（`cacheFileText`）；
取不到内容抛 `EvaluatorException`，脚本可以 `try/catch` 后走降级分支。

## 落地改动

- `rules/JavaPackages.kt`（新）：`Packages` 命名空间、43 个白名单类的贴片、`JavaImporter`、
  `importPackage`/`importClass`、okhttp3 同步贴片、`elementOf` 的 int 下标读取。
- `rules/ScriptCache.kt`（新）与 `data/ScriptCacheDao.kt`（新）：全局 `cache` 的内存+落盘两层。
- `data/Database.kt`：建 `script_cache` 表与 deadline 索引。
- `rules/ScriptHtml.kt`（新）：`htmlFormat` 的保图排版。
- `rules/JsMapObject.kt`（新）：登录信息/HashMap 的 Map 方法（`get`/`put`/`containsKey`…）。
- `rules/JsSandbox.kt`：安装 `cache`；`ajaxAll`；`getUserAgent`/`getWebViewUA`、`toURL`、
  `importScript`、`cacheFile`；`jsStringList` 改 int 下标；`importScript` 空内容改抛 `EvaluatorException`。
- `rules/ScriptCrypto.kt`：`toBytes` 支持 JS 数组（int 下标）、`CharSequence`、className 为 String
  的包装对象；`specBox` 补 `getFormat`/`getAlgorithm`/`getEncoded`。
- 测试：`JsCachePackagesBridgeTest.kt`（27 条）、`JsoupBridgeTest` 的反射断言改为
  「Class/Runtime/getClass 都不可达」、`JsResponseCookieTest` 跟随 `fetchFailureText` 迁到顶层。

## 验证

- 后端 `./gradlew :app:test`：887 条全绿（0.2.8 时为 860；新增 `JsCachePackagesBridgeTest` 27 条）。
- 前端 `npm test`：818 条全绿（含 `Changelog.test.ts` 对 0.2.9 条目的格式检查）。
- `node scripts/version-check.mjs`：7 处版本一致（0.2.9）；`gen-api-reference.mjs` 只改版本行。
- live：`tmp/triage_gap_029.py` 48 份抽样，脚本报错 11 → 2（见上）；失败面几乎全是站点侧。
- `node start.mjs` 起 0.2.9 后 `/healthz` 报 `version=0.2.9`。

## 遗留

- `java.t2s`/`java.s2t` 仍未实现（用到 quick-transfer，可作为下一个独立小项）。
- `java.webView`、`java.getVerificationCode` 需要真浏览器一档，服务端只应如实报「不支持」。
- `refreshTocUrl`/`refreshBookUrl`（依赖 preUpdateJs）、`queryTTF`、`BitmapFactory`、
  `AnalyzeRule`/`StrResponse` 构造器还没做。
- 按类型（漫画/音频/文件/视频）的活体抽检仍是长期项，站点可用性波动大，结论要按周看。
